# 评测体系与基准设计

## 1. 评测目标

INA 的评测不能只问“回答是否更好”，还要回答：

- cognition 是否被忠实迁移；
- 是否在未见任务上生效；
- 是否能跨模型；
- 是否可编辑和可回滚；
- 是否只是更长的 Prompt；
- 是否值得比直接 Fine-tuning 多一层 IR。

## 2. 必备基线

每个核心实验应尽量包含：

1. Vanilla Agent；
2. System Prompt；
3. Few-shot；
4. Memory；
5. RAG；
6. Human Checklist；
7. Sham INA；
8. Wrong-domain INA；
9. INA Prompt Backend；
10. INA Runtime Backend；
11. 直接 SFT / DPO / LoRA；
12. INA 编译到 SFT / DPO / LoRA。

首轮实验可分阶段加入训练基线，但研究计划必须保留。

## 3. 指标矩阵

### 任务结果

- Accuracy / Success Rate；
- Decision Quality；
- Tool-use Success；
- Cost 与 Latency。

### 认知迁移

- Policy Fidelity；
- Preference Fidelity；
- Scope Fidelity；
- Epistemic Fidelity；
- Compilation Fidelity。

### 泛化

- 未见任务增益；
- 表述变化鲁棒性；
- 跨模型迁移；
- 跨 Agent Framework 迁移。

### 认识论质量

- Stance Sensitivity；
- False-premise Rejection；
- Alternative Quality；
- Causal Direction Score；
- Falsification Quality；
- Calibration；
- Contrarianism Rate。

### IR 独特价值

- Editability；
- Auditability；
- Portability；
- Composability；
- Sample Efficiency；
- Adaptation Speed；
- Rollback Cost。

### 演化安全

- Drift；
- Regression；
- Catastrophic Forgetting；
- Cognitive Distance；
- Immunity Failure Rate。

## 4. 实验纪律

- 预先冻结任务集、指标和成功标准；
- 使用隐藏集；
- 多次重复并记录随机性；
- 人工评审尽量盲化；
- 对裁判模型做偏差检查；
- 报告所有主要负面结果；
- 不使用来源示范作为测试集；
- 记录模型、版本、温度、工具和上下文；
- 对改动做消融实验。

## 5. 核心对照问题

### INA vs Prompt

控制信息量和示范数量，检查 INA 是否只是一种包装。

### INA vs Direct Training

比较：

```text
trajectory → fine-tune
```

与：

```text
trajectory → INA → fine-tune
```

INA 需要证明至少一项：

- 更少数据；
- 更易编辑；
- 更好迁移；
- 更好审计；
- 更好组合；
- 更安全演化。

### Symbolic vs Neural

检查训练后的 Neural INA 是否丢失作用域、反证和失败边界。

### Correct vs Wrong INA

错误领域 INA 应明显劣于正确 INA，否则说明路由或表示没有真正作用。

## 6. 证据等级

| 等级 | 含义 |
|---|---|
| E0 | 只有概念和示例 |
| E1 | 单次 Demo |
| E2 | 可重复的内部对照 |
| E3 | 隐藏集与多模型复现 |
| E4 | 外部团队复现 |
| E5 | 真实长期部署和结果证据 |

任何市场验证标签都应显示证据等级。
