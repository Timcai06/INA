# 认知进化、谱系与嫁接

## 1. 稳定核心与可进化外围

INA 的成长不是全部字段同时变化。

建议分为：

```text
稳定核心
  认识论底线、证据诚实、修正能力

领域方法
  可通过领域实验逐步优化

个体偏好
  可随用户长期交互快速变化
```

不同层使用不同的变更门槛。

## 2. 进化流程

```text
新经验或结果
      ↓
失败分类与责任归因
      ↓
Mutation Candidate
      ↓
Quarantine
      ↓
Replay + Regression
      ↓
Cognitive Distance 检查
      ↓
人工或策略审批
      ↓
发布新版本
      ↓
持续监控 / 回滚
```

## 3. Cognitive Credit Assignment

一次任务的结果必须在多个因素间归因：

- 基础模型；
- INA；
- 检索；
- 工具；
- 上下文；
- 执行环境；
- 随机性；
- 未知。

只有 INA 责任达到证据阈值，才允许修改认知适配器。

## 4. Replay 与回归保护

每个成熟 INA 必须维护：

- 历史成功样例；
- 已知失败样例；
- 边界条件；
- 认识论宪法测试；
- 关键用户场景；
- 冲突测试。

候选版本需要满足：

```text
新任务表现提升
历史能力无显著下降
核心宪法保持
已知失败不扩大
```

## 5. Cognitive Distance

用于衡量两个 INA 版本之间的认知变化程度。

可以包含：

- 规则新增与删除；
- 优先级改变；
- Preference Reversal；
- 作用域变化；
- 宪法变化；
- 示例分布变化；
- 路由阈值变化。

大幅变化必须提升审查等级。

## 6. 谱系

谱系记录的不只是版本号，而是：

- 父版本；
- 继承了什么；
- 修改了什么；
- 删除了什么；
- 为什么变化；
- 哪些证据支持；
- 在什么 Benchmark 上更好或更差；
- 是否允许继续派生。

示例：

```text
架构决策 INA v1
├── 创业团队变体 v1
│   └── 端侧应用变体 v2
└── 金融合规变体 v1
```

## 7. INA Graft

Graft 的流程：

1. 明确目标领域和任务；
2. 识别多个 INA 的适用范围；
3. 检测优先级、价值、流程和风险冲突；
4. 解析冲突；
5. 发现跨领域协同；
6. 生成新的 Symbolic INA；
7. 与独立加载和简单合并进行对照评测。

成功标准必须是：

> Grafted INA 超过 A、B、A+B 独立加载和自然语言拼接基线。

## 8. 交易与衍生权

谱系是可交易性的基础。

每个可派生 INA 应记录：

- 原作者；
- 当前维护者；
- 许可；
- 是否允许修改；
- 是否允许商业使用；
- 衍生收益规则；
- 撤销和安全更新传播方式。

具体分成比例属于未来市场规则，不在本阶段冻结。
