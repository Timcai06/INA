# 研发路线图与阶段门禁

## 1. 原则

路线图不以固定月份作为主要承诺，而以证据门槛决定是否进入下一阶段。

产品 UI 和完整 PRD 当前不是重点。第一批工作是文档、协议、实验和核心模块。

## 2. 阶段 0：文档与研究基线

### 目标

统一概念、假设、Schema 和评测方法。

### 交付

- 本文档矩阵；
- Claim Register；
- Schema v0.3 Draft；
- 首个实验设计；
- ADR 规范；
- 基线仓库结构。

### 门禁

团队成员对 INA 的定义、非目标和首个实验没有关键歧义。

## 3. 阶段 1：人工 Symbolic INA

### 目标

不依赖自动提取，先验证独立认知表示能否工作。

### 交付

- 一个软件工程 Cognitive Adapter；
- Prompt Compiler；
- 最小 Runtime；
- Trajectory Logger；
- Vanilla、Prompt、Checklist 基线。

### 门禁

在隐藏任务上出现可重复、可解释的行为差异。

## 4. 阶段 2：评测与表示修正

### 目标

证明或否定 Schema 的有效性。

### 交付

- Benchmark；
- 盲评工具；
- Sham / Wrong-domain INA；
- 消融实验；
- Compilation Fidelity 指标。

### 门禁

INA 相比最强 Prompt 基线至少提供一项可量化独特价值，否则收缩或重构定义。

## 5. 阶段 3：INA-seq Lite

### 目标

从轨迹半自动提出候选 cognition。

### 交付

- 决策点检测；
- 候选策略归纳；
- 示范、反例和 Preference Pair 生成；
- 人工审查；
- Fidelity 评测。

### 门禁

提取结果在未见任务上复现来源 cognition，且明显优于表面总结。

## 6. 阶段 4：多 Backend 编译

### 目标

验证 INA 作为 IR，而不是单一 Runtime 配置。

### 交付

- Prompt Backend；
- Runtime Backend；
- SFT Dataset Compiler；
- DPO Pair Compiler；
- 直接训练对照；
- Compilation Loss 报告。

### 门禁

至少两个 Backend 保留核心语义，且 INA 层带来可编辑、数据效率、迁移或审计价值。

## 7. 阶段 5：安全进化

### 目标

实现 Credit Assignment、Replay、Regression、Cognitive Distance 和 Rollback。

### 门禁

候选更新能提升新任务且不破坏历史保留集和核心宪法。

## 8. 阶段 6：路由、谱系和 Graft

### 目标

支持多个认知适配器的按需激活与可验证组合。

### 门禁

路由优于全部注入；Graft 优于简单拼接和独立加载。

## 9. 阶段 7：Registry、企业与市场验证

### 目标

在核心认知资产成立后验证：

- 免费 Agent 调用模型；
- Team / Enterprise 私有 Registry；
- 端侧部署；
- 许可与交易；
- 个人 INA。

### 门禁

存在真实复用、付费或企业部署证据，而不是仅有访谈兴趣。

## 10. 首批可并行工作流

### A：Schema 与协议

负责文档 04、05、08。

### B：评测与数据

负责文档 03、09、14。

### C：Runtime 与 Compiler

负责文档 06、10。

### D：研究治理

负责 Claim、风险、ADR 和实验留痕。

商业和产品设计仅做约束输入，不占用早期主开发资源。

## 11. 停止条件

遇到以下情况应暂停扩张：

- 与 Prompt 无法区分；
- 提取结果不稳定；
- Direct Fine-tuning 全面更优且 INA 无治理增益；
- 进化不可控；
- 跨模型需要完全重写；
- 用户不愿为认知资产复用付费；
- 市场所需权利和来源无法证明。
