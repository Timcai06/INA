# 商业模式与认知市场

## 1. 文档定位

本文件只定义长期商业原则和必须预留的技术条件，不展开完整产品形态、界面、销售流程和价格表。

所有商业判断当前都属于待验证假设。

## 2. 核心价值链

```text
Agent 调用
  ↓
积累可观测经验
  ↓
形成和验证认知适应
  ↓
保存、迁移和复用
  ↓
成为个人、团队或企业认知资产
  ↓
授权、订阅、交易或私有部署
```

## 3. 免费额度

首阶段免费额度统一按照 **Agent 调用次数** 计算，而不是 Token、内部 Pattern 数或 INA Operation 数。

### 计费单位

一次 `Agent 调用`：

> 外部 Agent 为完成一个顶层任务，向 INA 服务发起一次认知请求并收到有效响应。

### 计数原则

- 一次调用内部激活多个认知单元，只计一次；
- 同一请求的流式输出只计一次；
- 服务端错误重试不计；
- 客户端重新发起的新请求计为新调用；
- 批量任务原则上按实际任务项计数；
- 具体反滥用规则在 API 阶段制定。

### 免费层目标

免费额度必须足够让开发者经历至少一个最小价值闭环：

```text
接入
→ 多次 Agent 调用
→ 形成或加载 INA
→ 感受到可见的判断变化
→ 再决定是否付费
```

当前不写死具体次数，以 `N 次 / 项目 / 周期` 表示。`N` 由三类数据确定：

1. 单次调用真实成本；
2. 用户达到首次价值所需调用量；
3. 免费到付费的转化实验。

首期对外展示的主单位始终是调用次数，而不是复杂内部计量。

## 4. 收费层次

### Developer Cloud

- 免费 Agent 调用额度；
- 超额后按调用次数计费；
- 高成本训练或大规模批处理可单独计价。

### Team

- 团队 INA 共享；
- 权限、版本和审核；
- 调用额度池；
- 私有 Registry。

### Enterprise / Edge

- 私有化部署；
- 本地 Runtime 和 Registry；
- 端侧 Compiled / Neural INA；
- 审计、撤销、策略治理；
- Air-gapped 场景；
- 定制支持与授权。

### Personal / To C

远期提供个人 INA：

- 跨 Agent 迁移；
- 长期认知成长；
- 私人认知资产管理；
- 购买和组合领域 INA。

企业端侧 Agent 属于 To B / Enterprise；个人 INA 才是主要 To C 方向。

## 5. 可交易性

可交易性必须保留为 INA 的核心属性。

市场交易的不是聊天记录，而是经过脱敏和验证的：

- Cognitive Adapter；
- Domain Methodology；
- Epistemic INA；
- Workflow Cognition；
- Team Template；
- Compiled INA；
- Neural Adapter 许可；
- 持续更新的 INA 订阅。

## 6. 交易方式

远期可支持：

- 免费公开；
- 一次性授权；
- 持续订阅；
- 按调用许可；
- 企业内部共享；
- 衍生 INA 分成；
- 定制 Graft。

市场抽成比例暂不冻结。

## 7. 市场可信度

一个可交易 INA 至少展示：

- 作者和所有权；
- 来源与脱敏声明；
- 许可；
- 适用范围；
- 版本和谱系；
- 兼容 Backend；
- Benchmark 与证据等级；
- 已知失败；
- 撤销状态；
- 更新频率。

星级和评论不能替代验证。

## 8. 企业端侧价值

企业部署端侧 Agent 时，需要解决：

- 多 Agent 使用何种认知政策；
- 企业方法如何在模型更换后继续存在；
- 如何在离线和受监管环境运行；
- 如何统一团队判断而不泄露原始数据；
- 如何审计一次认知变化；
- 如何撤销有缺陷的 INA。

因此企业场景可能需要：

```text
Private INA Registry
Local Runtime
Compiled / Neural INA
Policy Governance
Lineage
Audit
Internal Market
```

## 9. 商业顺序

1. 先让开发者免费体验真实价值；
2. 再验证按 Agent 调用收费；
3. 再验证 Team 与 Enterprise 私有治理；
4. 在资产标准和验证机制成熟后开放 Market；
5. To C Personal INA 作为长期扩展。

不能先建交易所，再证明认知资产是否存在。
