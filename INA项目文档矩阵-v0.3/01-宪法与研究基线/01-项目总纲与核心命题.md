# INA 项目总纲与核心命题

## 1. 愿景

> **DNA encodes life. INA encodes intelligence.**

这句话保留为 INA 的长期愿景，但不是已被证明的科学结论。

当前更严格的研究表达是：

> **INA 编码的不是 Agent 知道什么，而是经验如何改变它的判断方式，以及这种改变如何被表示、验证、迁移和继续演化。**

面向用户的直觉表达可以是：

> **Memory 让 Agent 记住你，INA 让 Agent 与你共同成长。**

## 2. 最新正式定义

INA 不再被定义为单纯的“结构化经验库”。

> **INA 是 Cognitive Adaptation 的中间表示。它把用户、Agent 与环境交互中形成的认知变化，表示为可显式检查的 Cognitive Adapter，并允许这些适配器通过 Prompt、Runtime 或模型训练重新作用于 Agent。**

它同时包含两层含义：

1. **Evolving Cognitive Architecture**：Agent 的认知会随着长期交互形成、修正和分化；
2. **Cognitive Adaptation IR**：认知变化不只停留在对话或模型权重里，而能被独立表示和处理。

## 3. INA 研究的对象

INA 关注的不是一般知识，而是以下认知变化：

- 如何定义问题；
- 应先收集什么证据；
- 如何保留竞争性假设；
- 怎样处理相关与因果；
- 如何衡量风险、成本和收益；
- 什么信号触发拒绝、升级或试验；
- 何时停止继续搜索；
- 信息不足时如何表达不确定性；
- 哪些结果足以修改现有策略；
- 如何避免被用户立场和错误反馈带偏。

## 4. INA 与邻近能力的区别

| 能力 | 回答的问题 |
|---|---|
| Knowledge / RAG | 外部世界有哪些相关资料？ |
| Memory | 过去发生了什么、用户偏好什么？ |
| System Prompt | 当前必须遵守什么指令？ |
| Workflow | 任务要经过哪些固定步骤？ |
| Fine-tuning | 如何把行为偏好内化进模型参数？ |
| INA | 经验形成了怎样的认知适应，这种适应如何独立存在并作用于不同 Agent？ |

## 5. 核心四步

### Extract

从轨迹、结果和反馈中识别候选 cognition。

### Represent

把 cognition 表示为可计算的 Cognitive Adapter。

### Compile

将适配器编译为 Prompt、Runtime Policy、SFT 数据、Preference Pair 或 Neural Adapter。

### Evolve

基于评测与认知归因安全更新，并保留谱系与回滚能力。

贯穿四步的横向能力是：

- Evaluate；
- Route；
- Immunize；
- Trace；
- Graft；
- Govern。

## 6. 核心设计原则

### 模型无关

INA 的语义不应绑定某一家模型或某一种 Agent Framework。

### 显式但不追求完全符号化

INA 只显式化值得控制、迁移和审计的认知部分，不试图替代神经模型的全部推理能力。

### 结论对用户立场低敏感、对证据高敏感

理解用户不等于赞同用户；独立思考也不等于机械唱反调。

### 成长必须可归因

一次失败不能直接修改认知。必须区分模型、工具、检索、上下文和 INA 自身的责任。

### 进化必须可回滚

任何认知变化都要经过隔离、Replay、回归评测和 Cognitive Distance 检查。

### 可交易性从协议层保留

INA 作为认知资产必须从一开始就具备来源、许可、版本、验证范围和谱系信息，即使市场平台暂缓建设。

## 7. 当前非目标

- 构造一个完整人格复制系统；
- 声称能够提取模型私有思维链；
- 用规则系统替代基础模型；
- 在一个阶段覆盖所有领域；
- 证明 INA Runtime 必须优于 Fine-tuning；
- 在没有证据时宣称 INA 是新的通用标准。

## 8. INA 成立的最低条件

INA 至少需要证明：

1. 可从经验中识别稳定的认知变化；
2. 这种变化能被独立表示；
3. 表示在至少一个执行后端中能再现有意义的行为效应；
4. 显式表示带来编辑、迁移、审计、组合或数据效率中的至少一种真实增益；
5. 整个过程可重复、可比较并允许失败。
