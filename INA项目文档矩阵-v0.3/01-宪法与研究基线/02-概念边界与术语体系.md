# 概念边界与术语体系

## 1. 正式术语

### 认知适应（Cognitive Adaptation）

Agent 因经验、结果或反馈而产生的稳定判断变化。它不是单次回答差异，而是能够影响后续同类任务的行为倾向。

### 认知适配器（Cognitive Adapter）

对一组认知适应的独立封装。它描述相对于某个 Base Agent 应增加、削弱或修改哪些认知行为。

### 认知增量（Cognitive Delta）

认知适配器相对于基准认知的变化量：

```text
C_agent =
C_base
+ ΔC_domain
+ ΔC_team
+ ΔC_user
```

`ΔC` 不代表完整人格，只代表可迁移的认知变化。

### 认知中间表示（Cognitive IR）

位于经验与最终模型行为之间的模型无关表示。它可以被编译到不同执行后端。

### 认识论宪法（Epistemic Constitution）

规定 Agent 如何形成、持有和修正信念的核心原则。

### 认知免疫（Cognitive Immunity）

防止用户 framing、谄媚、确认偏误、错误反馈和低质量继承污染认知的机制。

### 认知路由（Cognitive Routing）

根据当前上下文，只激活相关 INA 或认知单元，而不是把全部认知注入每次调用。

### INA-seq

从可观测轨迹、结果和评价中提取候选认知适应的过程。

### INA Compiler

把 Symbolic INA 转换为 Prompt、Runtime Policy、SFT 数据、Preference Pair、LoRA 或其他执行产物的编译系统。

### INA Runtime

在 Agent 运行过程中匹配、路由、注入和审计 INA 的执行层。它是执行后端之一，不再等同于 INA 本身。

### INA-evolve

通过认知归因、Replay、回归测试和版本门禁更新 INA 的过程。

### INA-lineage

记录 INA 的继承、变异、删除、融合、评测和派生关系。

### INA-graft

把多个认知适配器在目标领域中进行冲突解析和协同合成，而不是简单拼接。

## 2. 三种表示状态

### Symbolic INA

最显式的源表示，包含策略、示范、偏好对、证据、适用范围和评价契约。

### Compiled INA

面向具体运行时优化后的表示，如优化 Prompt、策略图或缓存后的 Runtime Program。

### Neural INA

经过 SFT、DPO、LoRA 等方式内化到参数或 Adapter 中的表示。

三者关系是：

```text
Symbolic INA
    ↓ compile
Compiled INA
    ↓ train / distill
Neural INA
```

反向从行为恢复 Symbolic INA 属于待验证能力，不是已成立事实。

## 3. “世界观”的使用边界

“世界观”适合帮助直觉理解 INA 的长期成长，但不作为首版 Schema 的单一字段。

工程上应拆为：

- **Epistemology**：凭什么相信；
- **Methodology**：如何解决问题；
- **Values / Preferences**：多个合理答案之间偏好什么。

INA 不应直接把某个哲学流派名称作为行为配置。哲学思想必须先被操作化为可观察原则，再经过评测。

## 4. 与其他概念的边界

| 概念 | 与 INA 的关系 |
|---|---|
| 用户画像 | 可以提供上下文，但不等于认知架构 |
| 长期记忆 | 记录事实和事件，是 INA-seq 的输入之一 |
| 规则引擎 | 可成为部分 Runtime 实现，但无法覆盖示范、偏好和不确定性 |
| Prompt | 可作为 INA 的编译产物，但不是 INA 的唯一表示 |
| Fine-tuning | 可作为 INA 的执行后端和强基线 |
| Agent Workflow | 描述任务流程；INA 描述流程背后的判断与适应 |
| Knowledge Graph | 表示实体和关系；INA 表示决策、证据和认知变化 |
| Persona | 偏向角色与表达；INA 关注可验证的认知行为 |
| Model Weights | 可承载 Neural INA，但通常缺乏显式可编辑性和谱系语义 |

## 5. 计量术语：Agent 调用

商业计量中的一次 `Agent 调用` 指：

> 一个外部 Agent 为完成一个顶层任务，向 INA 服务发起一次认知请求并获得一次有效响应。

首期原则：

- 同一 `request_id` 的流式输出只计一次；
- 一次调用内部激活多个 INA 单元不重复计数；
- 服务端故障导致的自动重试不计费；
- 客户端主动重新发起的新请求计为新调用；
- 批量任务的计数规则在 API 设计阶段明确，默认按实际任务项计数。

该定义服务于商业计费，不决定内部架构。
