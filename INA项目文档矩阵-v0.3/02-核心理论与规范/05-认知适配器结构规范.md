# 认知适配器结构规范

## 1. 目标

本规范定义 Symbolic INA 的最小逻辑结构。它是研究协议草案，不是冻结标准。

一个合格的 INA Cognitive Adapter 必须同时支持：

- 人工阅读与编辑；
- Runtime 激活；
- Prompt 编译；
- SFT / DPO 数据生成；
- 评测、谱系和交易审计。

## 2. 一级结构

```text
INA Cognitive Adapter
├── 身份与版本
├── 基准与认知增量
├── 适用范围
├── 语义策略
├── 认识论策略
├── 行为监督数据
├── 激活与路由
├── 来源与许可
├── 评价契约
└── 演化与谱系
```

## 3. 必填区块

### 身份与版本

- `id`
- `name`
- `schema_version`
- `adapter_version`
- `status`
- `domain`
- `created_at`

### 基准与认知增量

- `base_assumption`
- `delta_summary`
- `target_behavior`
- `non_goals`

必须明确“相对于什么基础”发生变化。

### 适用范围

- `applicable_when`
- `not_applicable_when`
- `preconditions`
- `required_context`
- `risk_level`

### 语义策略

- `rules`
- `priorities`
- `constraints`
- `investigation_sequence`
- `exceptions`
- `stop_conditions`
- `fallbacks`

### 认识论策略

- `evidence_requirements`
- `competing_hypotheses`
- `causal_checks`
- `falsification_rules`
- `uncertainty_policy`
- `revision_conditions`

### 行为监督数据

- `demonstrations`
- `counterexamples`
- `preference_pairs`
- `edge_cases`

规则不是唯一载体。示范、反例和偏好对是 INA 的一等数据。

### 激活与路由

- `triggers`
- `activation_threshold`
- `router_features`
- `conflict_priority`
- `deactivation_conditions`

### 来源与许可

- `source_trajectories`
- `extraction_method`
- `reviewers`
- `evidence`
- `owner`
- `license`
- `transfer_rights`
- `privacy_classification`

可交易性要求权利和来源从 Schema 第一版就存在。

### 评价契约

- `benchmarks`
- `baselines`
- `metrics`
- `holdout_sets`
- `minimum_thresholds`
- `revision_triggers`
- `known_failures`

### 演化与谱系

- `parents`
- `inheritance_map`
- `mutations`
- `credit_assignment`
- `replay_suite`
- `cognitive_distance`
- `rollback_target`

## 4. 示例骨架

```yaml
ina:
  schema_version: "0.3"
  identity:
    id: "ina-software-architecture-independence"
    name: "软件架构独立判断适配器"

    status: "experimental"
    domain: ["software-engineering"]

  cognitive_delta:
    base_assumption: "通用对话 Agent"
    delta_summary:
      - "不把用户技术偏好作为证据"
      - "重大迁移前生成多个竞争方案"
      - "优先寻找可区分方案的证据"

  scope:
    applicable_when: ["技术选型", "架构迁移"]
    not_applicable_when: ["最终安全审批"]
    required_context: ["团队规模", "现有架构", "运行约束"]

  semantic_policy:
    priorities:
      - "问题约束优先于技术潮流"
      - "可逆试验优先于不可逆迁移"
    investigation_sequence: []
    stop_conditions: []
    fallbacks:
      - "证据不足时建议小范围试验"

  epistemic_policy:
    user_stance_is_evidence: false
    minimum_competing_hypotheses: 2
    causal_direction_audit: true
    falsification_required: true
    uncertainty_required: true

  behavioral_supervision:
    demonstrations: []
    counterexamples: []
    preference_pairs: []

  activation:
    triggers: ["迁移", "重构", "技术替换"]
    activation_threshold: 0.70
    conflict_priority: "domain-over-user-preference"

  provenance:
    source_trajectories: []
    extraction_method: "manual"
    reviewers: []
    owner: ""
    license: "未指定"

  evaluation_contract:
    baselines: ["vanilla", "system-prompt", "few-shot", "human-checklist"]
    metrics: ["decision-quality", "stance-sensitivity", "policy-fidelity"]
    known_failures: []

  evolution:
    parents: []
    mutations: []
    replay_suite: []
    rollback_target: null
```

## 5. 状态机

建议状态：

```text
draft
→ candidate
→ experimental
→ validated
→ production
→ deprecated / revoked
```

“Validated” 必须绑定具体任务、模型、版本和指标，不能成为永久通用标签。

## 6. 兼容与交易要求

任何公开发布的 INA 至少需要公开：

- 适用范围；
- 兼容 Backend；
- 版本；
- 许可；
- 验证条件；
- 已知失败；
- 谱系；
- 最近更新时间。

不得仅凭作者名或星级声称“专家级”。
