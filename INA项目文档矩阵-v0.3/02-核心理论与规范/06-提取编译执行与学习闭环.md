# 提取、编译、执行与学习闭环

## 1. 完整闭环

```text
用户 / Agent / 环境交互
        ↓
可观测轨迹与结果
        ↓
INA-seq
        ↓
候选认知适应
        ↓
验证与人工审查
        ↓
Symbolic INA
        ↓
Cognitive Compiler
 ┌──────────┼───────────┐
 ↓          ↓           ↓
Prompt    Runtime     Training
                       ↓
                 SFT / DPO / LoRA
 └──────────┬───────────┘
            ↓
        Agent 行为
            ↓
          评测
            ↓
       认知责任归因
            ↓
       进化候选与回归
            ↓
      接受 / 拒绝 / 回滚
```

## 2. INA-seq 输入

首版只使用可观测数据：

- 用户任务与上下文；
- 提供给 Agent 的资料；
- 搜索与检索行为；
- 工具调用顺序和结果；
- 显式结构化判断；
- 最终建议或行动；
- 任务结果；
- 人工评价和用户反馈；
- 失败类型。

不把模型私有思维链设为必要输入。

## 3. INA-seq 阶段

1. 轨迹标准化；
2. Episode 与决策点分段；
3. 候选模式归纳；
4. 相似任务一致性检查；
5. 反例与例外搜索；
6. 作用域提取；
7. 行为示范和偏好对生成；
8. 专家或规则审查；
9. 进入 Candidate 状态。

## 4. 编译 Backend

### Prompt Backend

把 INA 转换为适合当前模型的系统提示、上下文片段或动态指令。

优势：低成本、快速验证、易编辑。  
风险：Context 占用、执行不稳定、容易退化为普通 Prompt。

### Runtime Backend

由路由器和策略执行器按情境激活认知单元。

优势：可控、可审计、可组合。  
风险：工程复杂、延迟和模型遵循度。

### SFT Backend

由 Demonstration 生成监督训练数据。

优势：可内化稳定行为。  
风险：数据质量、过拟合和更新成本。

### DPO Backend

由 Preference Pair 生成 chosen/rejected 数据。

优势：适合表达难以形式化的行为偏好。  
风险：偏好数据可能过于表面，丢失作用域。

### LoRA / Adapter Backend

把稳定、高频 cognition 编译为参数增量。

优势：推理效率高、可部署到端侧。  
风险：可解释性下降、组合和回滚需要额外管理。

## 5. 从微调逻辑吸收的设计

### Demonstration First

INA 不只保存规则，也保存“在什么情境下应该怎样做”的示范。

### Preference Relation

很多 cognition 不是布尔规则，而是：

```text
行为 B ≻ 行为 A
```

### Credit Assignment

失败后先判断责任来自：

- INA；
- 基础模型；
- 检索；
- 工具；
- 上下文；
- 随机性；
- 未知原因。

### Replay

新变化必须在历史保留集上回归。

### Regularization

无足够证据时，应惩罚大幅 Cognitive Delta。

### Routing

不是所有 INA 每次都激活。Router 只选择与上下文相关的少数适配器。

## 6. 热认知与稳定认知

建议分层：

```text
Runtime INA
  适合快速变化、个人化和近期经验

Compiled / Neural INA
  适合长期稳定、高频和低延迟 cognition
```

稳定 cognition 可以逐步下沉到 Training Backend；快速变化继续留在 Symbolic/Runtime 层。

## 7. 关键数据契约

每次执行至少记录：

- `request_id`
- 激活的 INA 与版本；
- 激活理由和置信度；
- 实际使用的 Backend；
- 发生的冲突和解决结果；
- 输出或行动；
- 评价；
- 是否进入进化候选。

这些日志既是评测资产，也是后续 INA-seq 的输入。
