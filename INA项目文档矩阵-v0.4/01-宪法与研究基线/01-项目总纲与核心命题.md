# INA 项目总纲与核心命题

## 1. 愿景

> **DNA encodes life. INA encodes intelligence.**

这句话保留为 INA 的长期愿景，但不是已被证明的科学结论。

当前更严格的研究表达是：

> **INA 让 Agent 的成长从不可见的副作用，变成可定义、可测试、可迁移、可治理的工程对象。**

面向用户的直觉表达可以是：

> **Memory 让 Agent 记住过去，INA 让 Agent 真正从过去中成长。**

但必须解释：这里的"成长"是指被明确验证并接受的 Behavioral Delta，而不是多了一块 Memory。

## 2. 正式定义

> **INA 是一个 Verified Behavioral Adaptation Control Plane。**

它不负责规定 Agent 必须通过什么机制学习。

它负责：

> **定义、验证、迁移、治理和回滚 Agent 究竟学会了什么行为/判断变化。**

INA **不是**一种新的 Memory、Skill 或 Agent Harness。

Memory、Skills、Harness、RL、Fine-tuning 都可以让 Agent 改变。INA 要解决的是：这种改变究竟是什么，它为什么发生，它有没有真正生效，它是否伤害了其他能力，它能否迁移到另一个 Agent，以及它能否被安全地批准、版本化和回滚。

## 3. 核心公式

```text
Base Agent
+
Behavioral Adaptation Δ
=
Adapted Agent
```

对某一个 Harness h：

```text
Effect_h(Δ)
=
Behavior(A_h + Realize_h(Δ))
-
Behavior(A_h)
```

INA 真正关心的是：

```text
Effect_Claude(Δ)
Effect_Codex(Δ)
Effect_Grok(Δ)
Effect_OpenCode(Δ)
```

是否表现为相近的：

- 方向；
- 核心行为变化；
- 作用域；
- failure boundary；
- invariant preservation。

核心是：**Baseline-relative Behavioral Effect**。

## 4. 一等对象

### Behavioral Delta / Cognitive Delta

相对于 Base Agent 的可测量行为变化。

> Cognitive Delta 的语义最终必须通过 observable behavioral effect 定义，而不能只通过自然语言描述定义。

### Cognitive State（重新定义）

> 一个 Agent 当前已经通过验证并被接受的 Cognitive / Behavioral Delta 的逻辑集合。

```text
Cognitive State(t)
=
Accepted Δ1 + Accepted Δ2 + ... + Accepted Δn
```

它是 logical state，而不是必须存在一个 cognitive-state database。

### Realization

同一个 Delta 在某一个 Harness 上的具体实现。

```text
Claude Code → Skill + CLAUDE.md + Hook
Codex → Skill + AGENTS.md + Rule
Grok → Skill + Hook
OpenCode → Agent Prompt + Permission + Plugin
```

Realization ≠ Delta 本身。

## 5. INA 研究的对象

INA 关注的不是一般知识，而是以下行为变化：

- 如何定义问题；
- 应先收集什么证据；
- 如何保留竞争性假设；
- 怎样处理相关与因果；
- 如何衡量风险、成本和收益；
- 什么信号触发拒绝、升级或试验；
- 何时停止继续搜索；
- 信息不足时如何表达不确定性；
- 哪些结果足以修改现有策略；
- 如何避免被用户立场和错误反馈带偏。

## 6. INA 与邻近能力的区别

| 能力 | 回答的问题 | 与 INA 的关系 |
|---|---|---|
| Knowledge / RAG | 外部世界有哪些相关资料？ | 不同层次 |
| Memory | 过去发生了什么、用户偏好什么？ | Memory 可能保存判断策略；INA 的独立性来自 semantics + lifecycle + evaluation contract |
| System Prompt | 当前必须遵守什么指令？ | Prompt 可作为 realization |
| Workflow | 任务要经过哪些固定步骤？ | Workflow 描述流程；INA 描述流程背后的判断与适应 |
| Fine-tuning | 如何把行为偏好内化进模型参数？ | Fine-tuning 是一种 realization |
| Agent Skills | 可复用的 Agent 能力包 | Skills 是一种 realization；INA 提供 verified behavioral adaptation 层 |
| INA | Agent 学会了什么行为变化，这种变化是否生效、能否迁移、能否治理？ | — |

## 7. 核心设计原则

### 模型无关

INA 的语义不应绑定某一家模型或某一种 Agent Harness。

### 显式但不追求完全符号化

INA 只显式化值得控制、迁移和审计的行为变化，不试图替代神经模型的全部推理能力。

### 结论对用户立场低敏感、对证据高敏感

理解用户不等于赞同用户；独立思考也不等于机械唱反调。

### 成长必须可归因

一次失败不能直接修改行为。必须区分模型、工具、检索、上下文和 INA 自身的责任。

### 变化必须可回滚

任何 Behavioral Delta 都要经过隔离、Replay、回归评测和版本检查。

### 可交易性从协议层保留

Adaptation Contract 必须从一开始就具备来源、许可、版本、验证范围和谱系信息，即使市场平台暂缓建设。

### 允许实验杀死自己

尤其：**Skill Equivalence** 和 **Cross-Harness Fidelity** 是核心 Kill Gates。

## 8. 当前非目标

- 构造一个完整人格复制系统；
- 声称能够提取模型私有思维链；
- 用规则系统替代基础模型；
- 在一个阶段覆盖所有领域；
- 声称 INA 是新的通用标准（除非实验证明）；
- 在 Marketplace / Enterprise Platform 上投入早期资源。

## 9. INA 成立的最低条件

INA 至少需要证明：

1. Behavioral Delta 可从经验中被识别和定义；
2. 这种 Delta 可以通过 Adaptation Contract 被显式表示；
3. 不同 realization 在不同 Harness 上产生方向一致的 baseline-relative effect；
4. 显式表示带来编辑、迁移、审计、组合或数据效率中的至少一种真实增益；
5. Skill Equivalence Kill Test 没有杀死 INA；
6. 整个过程可重复、可比较并允许失败。
