# INA v0.4 核心定义参考

## 版本主题

**Verified Behavioral Adaptation**

## 核心定义

> **INA 是一个 Verified Behavioral Adaptation Control Plane。**

它不负责规定 Agent 必须通过什么机制学习。

它负责：

> **定义、验证、迁移、治理和回滚 Agent 究竟学会了什么行为/判断变化。**

## 一等对象

### Behavioral Delta / Cognitive Delta

相对于 Base Agent 的可测量行为变化。

v0.4 中最重要的一等对象不再是模糊的 Cognitive State，而是 Behavioral Delta（或 Cognitive Delta）。

> Cognitive Delta 的语义最终必须通过 observable behavioral effect 定义，而不能只通过自然语言描述定义。

### Cognitive State（重新定义）

> **一个 Agent 当前已经通过验证并被接受的 Cognitive / Behavioral Delta 的逻辑集合。**

```text
Cognitive State(t)
=
Accepted Δ1
+
Accepted Δ2
+
...
+
Accepted Δn
```

它是 logical state，而不是必须存在一个 cognitive-state database。

## 核心公式

```text
Base Agent
+
Behavioral Adaptation Δ
=
Adapted Agent
```

对某一个 Harness h：

```text
Effect_h(Δ)
=
Behavior(A_h + Realize_h(Δ))
-
Behavior(A_h)
```

INA 真正关心的是：

```text
Effect_Claude(Δ)
Effect_Codex(Δ)
Effect_Grok(Δ)
Effect_OpenCode(Δ)
```

是否表现为相近的：

- 方向；
- 核心行为变化；
- 作用域；
- failure boundary；
- invariant preservation。

核心是：**Baseline-relative Behavioral Effect**。

## 新增核心概念

### 1. Behavioral Delta / Cognitive Delta

相对于 Base Agent 的可测量行为变化。

### 2. Adaptation Contract

一个 Delta 不是一句自然语言原则。它至少应该表达：

```text
Identity
Scope
Activation Conditions
Desired Behavioral Effects
Semantic Invariants
Forbidden Regressions
Revision Conditions
Evidence
Provenance
Evaluation Contract
Version
Lineage
```

### 3. Realization

同一个 Delta 在某一个 Harness 上的具体实现。

例如：

```text
Claude Code
→ Skill + CLAUDE.md + Hook

Codex
→ Skill + AGENTS.md + Rule

Grok
→ Skill + Hook

OpenCode
→ Agent Prompt + Permission + Plugin
```

Realization ≠ Delta 本身。

### 4. Cross-Harness Semantic Fidelity

同一个 Delta 在多个 Harness 中通过不同 realization 后：

> 是否产生方向一致、语义一致的 baseline-relative behavioral effect。

### 5. Behavioral Conformance

验证某一个 Agent / Harness / Model 的 realization：

> 是否符合 Adaptation Contract。

### 6. Effect Vector

例如：

```text
Δ alternative_generation
Δ evidence_seeking
Δ user_prior_weight
Δ reversible_experiment_preference
Δ disconfirmation_reporting
Δ task_success
Δ refusal_rate
Δ cost
```

INA 不应该只比较单个总分。

### 7. Adaptation Learner

任何能够提出 candidate Δ 的机制都属于外部/上游 Learner：

```text
Human authoring
Memory consolidation
SkillOpt-like learner
Bayesian evolution
Harness evolution
RL
Fine-tuning
Trajectory miner
LLM reflection
```

INA 不需要重新发明它们。

## 七条统一原则

### Principle 1

INA 不发明 Agent 如何学习。

INA 定义、验证和治理 Agent 学会了什么。

### Principle 2

Cognitive State 是逻辑状态，不是必须独立存在的物理存储。

### Principle 3

Skill / Memory / Hook / Prompt / Rule / Steering / Weight 都只是 realization。

### Principle 4

INA 的语义由 behavioral effect + evaluation contract 定义。

不是由自然语言文件本身定义。

### Principle 5

跨 Harness 的目标不是输出相同。

目标是：**baseline-relative effect semantic equivalence**。

### Principle 6

INA 必须允许实验杀死自己。

尤其：**Skill Equivalence** 和 **Cross-Harness Fidelity**。

### Principle 7

当前项目阶段：**Research + Phase-0 Engineering**。

不是：Marketplace / Enterprise Platform / Cognitive OS。

## 项目基调

> **INA 不发明 Agent 如何学习。**

> **Memory、Skills、Harness、RL、Fine-tuning 都可以让 Agent 改变。**

> **INA 要解决的是：这种改变究竟是什么，它为什么发生，它有没有真正生效，它是否伤害了其他能力，它能否迁移到另一个 Agent，以及它能否被安全地批准、版本化和回滚。**

最终核心句：

> **INA makes agent adaptation explicit, testable, portable, and governable.**

中文：

> **INA 让 Agent 的成长从不可见的副作用，变成可定义、可测试、可迁移、可治理的工程对象。**
