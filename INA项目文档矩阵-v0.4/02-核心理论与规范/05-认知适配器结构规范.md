# Adaptation Contract 结构规范

## 1. 目标

本规范定义 Adaptation Contract 的最小逻辑结构。它是研究协议草案，不是冻结标准。

主 Artifact 从 v0.3 的 "Cognitive Adapter" 改为 **Adaptation Contract**。

> Adapter 重新定义为：某个 Harness 对一个 Adaptation Contract 的 realization package。

一个合格的 Adaptation Contract 必须同时支持：

- 人工阅读与编辑；
- Realization 激活；
- Prompt / Skill 编译；
- 评测、谱系和交易审计；
- Cross-Harness Semantic Fidelity 验证。

## 2. 一级结构

```text
Adaptation Contract
├── Identity
├── Base Agent
├── Desired Effects
├── Scope
├── Semantic Invariants
├── Forbidden Regressions
├── Evaluation Contract
├── Evidence & Provenance
├── Realization Targets
└── Lineage
```

## 3. 必填区块

### Identity

- `id`：唯一标识
- `name`：人类可读名称
- `schema_version`：Schema 版本
- `contract_version`：Contract 版本
- `status`：draft / candidate / validated / accepted / deprecated
- `domain`：适用领域
- `created_at`：创建时间

### Base Agent

- `baseline`：基准 Agent 描述
- `baseline_behavior`：基准行为特征
- `delta_summary`：相对于基准的变化摘要

必须明确"相对于什么基础"发生变化。

### Desired Effects

- `effect_vector`：期望的行为变化维度
- `direction`：每个维度的期望方向（increase / decrease / maintain）
- `magnitude`：期望的变化幅度（qualitative 或 quantitative）
- `non_goals`：明确不属于此 delta 的目标

### Scope

- `applicable_when`：适用条件
- `not_applicable_when`：不适用条件
- `preconditions`：前置条件
- `required_context`：需要的上下文信息
- `risk_level`：风险等级

### Semantic Invariants

- `invariants`：不可违反的语义约束
- `must_preserve`：必须保持的能力
- `compilation_loss_tolerance`：可接受的编译损失

### Forbidden Regressions

- `regression_targets`：禁止退化的能力
- `regression_thresholds`：退化阈值
- `regression_tests`：对应的回归测试

### Evaluation Contract

- `baselines`：对照基线
- `metrics`：评测指标
- `holdout_sets`：隐藏集
- `minimum_thresholds`：最低通过标准
- `revision_triggers`：什么证据触发修订
- `known_failures`：已知失败场景
- `kill_criteria`：什么结果导致此 delta 被废弃

### Evidence & Provenance

- `source_trajectories`：来源轨迹
- `extraction_method`：提取方法
- `reviewers`：审查者
- `evidence_level`：证据等级（E0-E5）
- `owner`：所有者
- `license`：许可
- `transfer_rights`：转让权
- `privacy_classification`：隐私分类

### Realization Targets

- `target_harnesses`：目标 Harness 列表
- `realization_formats`：支持的 realization 格式
- `cross_harness_fidelity`：跨 Harness 保真度要求

### Lineage

- `parents`：父版本
- `inheritance_map`：继承映射
- `mutations`：变更记录
- `rollback_target`：回滚目标
- `lineage_tree`：谱系树

## 4. 示例骨架

```yaml
adaptation_contract:
  schema_version: "0.4"
  identity:
    id: "ac-software-architecture-independence"
    name: "软件架构独立判断"
    contract_version: "0.1.0"
    status: "experimental"
    domain: ["software-engineering"]
    created_at: "2026-08-18"

  base_agent:
    baseline: "通用对话 Agent"
    baseline_behavior:
      - "倾向于赞同用户技术偏好"
      - "倾向于选择单一方案"
      - "缺乏竞争性假设意识"
    delta_summary:
      - "不把用户技术偏好作为证据"
      - "重大迁移前生成多个竞争方案"
      - "优先寻找可区分方案的证据"

  desired_effects:
    effect_vector:
      - dimension: "alternative_generation"
        direction: "increase"
        description: "保留至少两个竞争方案"
      - dimension: "evidence_seeking"
        direction: "increase"
        description: "主动寻找可区分方案的证据"
      - dimension: "user_prior_weight"
        direction: "decrease"
        description: "降低用户偏好的决策权重"
      - dimension: "reversible_experiment_preference"
        direction: "increase"
        description: "优先选择可逆试验"
    non_goals:
      - "机械反对用户"
      - "替代基础模型的推理能力"

  scope:
    applicable_when:
      - "技术选型"
      - "架构迁移"
      - "重大重构决策"
    not_applicable_when:
      - "最终安全审批"
      - "紧急生产修复"
    required_context:
      - "团队规模"
      - "现有架构"
      - "运行约束"

  semantic_invariants:
    invariants:
      - "用户立场不是证据"
      - "重要结论必须说明修正条件"
    must_preserve:
      - "任务成功率"
      - "一般推理能力"
    compilation_loss_tolerance: "low"

  forbidden_regressions:
    regression_targets:
      - "task_success"
      - "general_capability"
      - "refusal_rate"
    regression_thresholds:
      task_success: "absolute -5%"
      general_capability: "relative -10%"

  evaluation_contract:
    baselines:
      - "vanilla_agent"
      - "system_prompt"
      - "native_skill"
    metrics:
      - "decision_quality"
      - "stance_sensitivity"
      - "alternative_quality"
      - "falsification_quality"
    minimum_thresholds:
      decision_quality: "≥ baseline"
      stance_sensitivity: "≤ 0.3"
    kill_criteria:
      - "native_skill + eval 完全等价"
      - "cross-harness fidelity < 0.5"

  evidence:
    evidence_level: "E0"
    source_trajectories: []
    extraction_method: "manual"

  provenance:
    owner: "INA Project"
    license: "TBD"
    privacy_classification: "team"

  realization_targets:
    target_harnesses:
      - "claude_code"
      - "codex"
      - "opencode"
    cross_harness_fidelity:
      min_direction_agreement: 0.7

  lineage:
    parents: []
    mutations: []
    rollback_target: null
```

## 5. 状态机

```text
draft
→ candidate
→ experimental
→ validated
→ accepted
→ production
→ deprecated / revoked
```

"Validated" 必须绑定具体 harness、model、version 和 metrics，不能成为永久通用标签。

## 6. 兼容与交易要求

任何公开发布的 Adaptation Contract 至少需要公开：

- 适用范围；
- 兼容 Harness；
- 版本；
- 许可；
- 验证条件；
- 已知失败；
- Kill Criteria；
- 谱系；
- 最近更新时间。

不得仅凭作者名或星级声称"专家级"。
