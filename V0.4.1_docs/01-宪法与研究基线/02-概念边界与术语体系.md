# 概念边界与术语体系

## 1. 正式术语

### Agent Baseline Fingerprint

用于唯一描述 Behavioral Delta 所比较的 Agent 基线，以及所有可能污染因果归因的关键运行变量。

```yaml
baseline_fingerprint:
  harness:      {name, version}
  model:        {provider, name, version, variant}
  system:       {prompt_hash, instruction_files, instruction_hashes}
  tools:        {enabled, versions}
  permissions:  {profile}
  skills:       {enabled, hashes}
  memory:       {mode, snapshot_id}
  runtime:      {temperature, reasoning_effort, context_policy, max_steps}
  environment:  {workspace_revision, relevant_flags}
```

关键原则：

> 只要某个变量可能改变行为并污染 Δ 的因果归因，它就应该进入 Fingerprint 或明确记录为 uncontrolled variable。

模型或 Harness 升级后，旧 Conformance Result 不得自动继承为有效。

### Behavioral Delta（行为增量）

相对于 Base Agent（给定 Baseline Fingerprint F）的可测量行为变化。这是 v0.4 的一等对象。

```text
Effect_h(Δ | F) = Behavior(A_h(F) + Realize_h(Δ)) - Behavior(A_h(F))
```

### Cognitive Delta（认知增量）

与 Behavioral Delta 可互换使用，但必须明确：

> Cognitive Delta 的语义最终必须通过 observable behavioral effect 定义，而不能只通过自然语言描述定义。

### Adaptation Contract（适配契约）

一个 Delta 不是一句自然语言原则。它至少应该表达：

| 字段 | 说明 |
|---|---|
| Identity | 唯一标识、版本 |
| Scope | 适用范围、前置条件 |
| Activation Conditions | 何时激活 |
| Desired Behavioral Effects | 期望的行为变化 |
| Semantic Invariants | 不可违反的语义约束 |
| Forbidden Regressions | 禁止退化的能力 |
| Revision Conditions | 什么证据可以修改此 Delta |
| Evidence | 支持此 Delta 的证据 |
| Provenance | 来源、作者、许可 |
| Evaluation Contract | 如何验证此 Delta |
| Version | 版本号 |
| Lineage | 谱系关系 |

### Realization（实现）

同一个 Delta 在某一个 Harness 上的具体实现。

```text
Claude Code → Skill + CLAUDE.md + Hook
Codex → Skill + AGENTS.md + Rule
Grok → Skill + Hook
OpenCode → Agent Prompt + Permission + Plugin
```

Realization ≠ Delta 本身。

### Behavioral Effect（行为效应）

Delta 在特定 Harness 上、给定 Baseline Fingerprint F 下产生的实际行为变化。

```text
Effect_h(Δ | F) = Behavior(A_h(F) + Realize_h(Δ)) - Behavior(A_h(F))
```

### Effect Vector（效应向量）

多维度的行为变化测量，不是单一分值。

```text
Δ alternative_generation
Δ evidence_seeking
Δ user_prior_weight
Δ reversible_experiment_preference
Δ disconfirmation_reporting
Δ task_success
Δ refusal_rate
Δ cost
```

### Behavioral Conformance（行为合规）

验证某一个 Agent / Harness / Model 的 realization 是否符合 Adaptation Contract。

### Cross-Harness Semantic Fidelity（跨 Harness 语义保真）

同一个 Delta 在多个 Harness 中通过不同 realization 后，是否产生方向一致、语义一致的 baseline-relative behavioral effect。

### Adaptation Learner（适配学习器）

任何能够提出 candidate Δ 的机制：

```text
Human authoring
Memory consolidation
SkillOpt-like learner
Bayesian evolution
Harness evolution
RL
Fine-tuning
Trajectory miner
LLM reflection
```

INA 不需要重新发明它们。

INA 的边界：

```text
Adaptation Learner  →  Candidate Delta  →  INA Validation  →  Accepted Delta
```

Adaptation Learner 负责产生候选；INA 负责验证、治理和迁移。

### Accepted Delta（已接受 Delta）

通过验证并被批准纳入 Cognitive State 的 Behavioral Delta。

### Redefined Cognitive State（重新定义的认知状态）

> 一个 Agent 当前已经通过验证并被接受的 Cognitive / Behavioral Delta 的逻辑集合。

```text
Cognitive State(t) = Accepted Δ1 + Accepted Δ2 + ... + Accepted Δn
```

它是 logical state，而不是必须存在一个 cognitive-state database。

## 2. 重新定义的核心概念

### Memory

现代 Memory 可以保存：事实、事件、workflow、strategy、debugging pattern、procedural knowledge。

INA 的边界不再依赖"存储什么内容"，而依赖：

> **semantics + lifecycle + evaluation contract**

### Skill

Skill 是一种 realization。INA 不替代 Skills，INA 为 Skills 提供 verified behavioral adaptation 层。

### Harness

Harness 是执行环境。INA 通过 Adapter/Realization 与之集成，而不是成为另一个 Harness。

### Policy

Policy 是从状态或证据到行为/决策的映射。Behavioral Delta 是相对于某个 Baseline，对 Policy 或可观察行为产生的变化。Delta 可以修改、补充或约束 Policy，但 Policy 本身不等于 Delta。Epistemic Constitution 是一类非常重要的 Behavioral Policy。

### Cognitive State

见上文重新定义。不再是一个物理组件，而是逻辑状态。

## 3. 三种表示状态（保留）

### Symbolic State

作为源代码存在，适合编辑、审计、交易。

### Compiled State

针对某个 Runtime 或模型优化，适合快速执行。

### Neural State

以内化的参数增量存在，适合高频、低延迟 cognition。

三者关系：

```text
Symbolic → compile → Compiled → train → Neural
```

反向从行为恢复 Symbolic 属于待验证能力。

## 4. 与其他概念的边界

| 概念 | 与 INA 的关系 |
|---|---|
| 用户画像 | 可以提供上下文，但不等于认知架构 |
| 长期记忆 | 可能保存判断策略；INA 的独立性来自 lifecycle + evaluation |
| 规则引擎 | 可成为部分 realization，但无法覆盖示范、偏好和不确定性 |
| Prompt | 可作为 realization，但不是 INA 的唯一表示 |
| Fine-tuning | 可作为 realization 和强基线 |
| Agent Workflow | 描述任务流程；INA 描述流程背后的判断与适应 |
| Knowledge Graph | 表示实体和关系；INA 表示决策、证据和行为变化 |
| Persona | 偏向角色与表达；INA 关注可验证的行为 |
| Model Weights | 可承载 Neural INA，但通常缺乏显式可编辑性和谱系语义 |
| Agent Skills | Skills 是一种 realization；INA 提供 verification 层 |

## 5. 计量术语：Agent 调用

商业计量中的一次 Agent 调用：

> 一个外部 Agent 为完成一个顶层任务，向 INA 服务发起一次认知请求并获得一次有效响应。

首期原则：

- 同一 request_id 的流式输出只计一次；
- 一次调用内部激活多个 INA 单元不重复计数；
- 服务端故障导致的自动重试不计费；
- 客户端主动重新发起的新请求计为新调用；
- 批量任务的计数规则在 API 设计阶段明确，默认按实际任务项计数。

该定义服务于商业计费，不决定内部架构。
