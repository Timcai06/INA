# 研究章程与可证伪假设

## 1. 研究决策

本阶段研究需要支持的决策是：

> INA 是否值得作为一种独立的 Verified Behavioral Adaptation Control Plane 继续投入，以及首个可验证实现应采用什么最小表示和执行后端。

## 2. 核心问题

> 一个 behavioral adaptation 是否可以脱离具体 realization 被显式定义，并在多个不同 Harness 上产生方向一致的 baseline-relative effect？

这是 v0.4 的 **H-Core**。

## 3. 主假设

### H-Core：跨 Harness 语义保真

一个 behavioral adaptation 可以脱离具体 realization 被显式定义，并在多个不同 Harness 上产生方向一致的 baseline-relative effect。

### H1：可提取性（保留，限定）

相似任务轨迹中存在跨案例稳定的行为变化，而不只是语言风格或事后总结。

限定：合成日志、技术选型窄任务族、Symbolic 提取。

### H2：可表示性（重新定义）

行为变化可以被表示为包含 Adaptation Contract、Evaluation Contract、Evidence 和 Lineage 的独立 Artifact。

### H3：可执行性（保留，限定）

同一 Behavioral Delta 经过不同 realization 后，能在未见任务上稳定改变 Agent 行为。

限定：至少两个 Harness。

### H4：表示增益

相比直接 Prompt 或直接 Fine-tuning，INA 至少在可编辑性、数据效率、跨模型迁移、审计、组合或演化中提供一项显著价值。

### H5：可进化性（降级为远期）

在正确归因和回归保护下，INA 能从新经验中改善，而不发生不可控漂移。

## 4. 强反方假设

### H0-Skill：Native Skill 已足够

Native Agent Skill + ordinary Eval 已经足够，INA IR 没有额外价值。

这是项目最高优先级 Kill Gate。

### H0-Harness：Harness 即 adaptation state

Harness 本身就是完整 adaptation state，不需要独立 control-plane representation。

### H0-Eval：普通 Eval 已足够

普通 Agent Eval / Regression 工具已经足够，不需要 Behavioral Delta abstraction。

### H0-A：不存在稳定 cognition

所谓模式只是提取器对少量轨迹的过度解释。

### H0-B：INA 只是更复杂的 Prompt

去掉 JSON 和术语后，效果完全由自然语言指令解释。

### H0-C：直接训练更优

`trajectory → fine-tune` 始终比 `trajectory → INA → fine-tune` 更简单、效果相同，且 INA 没有带来额外治理价值。

### H0-D：认知无法稳定组合

不同 Behavioral Delta 在真实上下文中冲突严重，组合无法超过独立加载。

### H0-E：显式化得不偿失

解释、编辑和谱系带来的收益低于复杂度、延迟与性能损失。

## 5. 核心零假设总结

| 假设 | 内容 | 优先级 | Kill Gate Phase |
|---|---|---|---|
| H0-Skill | Native Skill + ordinary Eval 已足够 | 最高 | Phase 0B |
| H0-Harness | Harness 即 adaptation state | 高 | Phase 1 |
| H0-Eval | 普通 Eval 已足够 | 高 | Phase 0A |
| H0-A | 不存在稳定 cognition | 中 | Phase 0A |
| H0-B | INA 只是更复杂的 Prompt | 中 | Phase 0A |
| H0-C | 直接训练更优 | 中 | Phase 0A |

## 6. 研究范围

首阶段限定为：

- 文本和工具调用型 Agent；
- 可观测输入、检索、工具行为、结构化理由摘要、输出和结果；
- 软件工程决策中的窄任务族；
- 人工编写或半自动提取的 Behavioral Delta；
- 至少两个 Harness 的 realization 和 paired replay；
- Prompt 和 Skill 作为第一批 realization；
- SFT、DPO 和 LoRA 作为后续强基线。

首阶段不依赖模型私有思维链。

## 7. 证据要求

每个核心 Claim 必须记录：

- Claim 内容；
- 当前状态；
- 所需证据；
- 首选来源；
- 反方解释；
- 置信度；
- 修正触发器；
- 对应实验。

## 8. 初始 Claim Register

| 编号 | Claim | 状态 | 关键证据 | 否定信号 |
|---|---|---|---|---|
| C-01 | 轨迹中存在稳定行为变化 | 待验证 | 多任务一致性与专家盲评 | 提取结果不稳定 |
| C-02 | Behavioral Delta 可独立表示 | 待验证 | 跨 Harness 语义保持 | 必须为每个 Harness 重写 |
| C-03 | Delta 能改变未见任务行为 | 待验证 | 隐藏集增益 | 只在示范案例有效 |
| C-04 | INA 提供 Prompt 之外的价值 | 待验证 | 编辑、迁移、审计等对照 | 仅等价于长 Prompt |
| C-05 | 同一 Delta 在多 Harness 上方向一致 | 待验证 | Cross-Harness Fidelity | 各 Harness 效果相反 |
| C-06 | Native Skill + Eval 不足以替代 INA | 待验证 | Skill Equivalence Test | Skill 方案完全等价 |
| C-07 | 认识论宪法降低谄媚 | 待验证 | Stance Sensitivity 测试 | 变成机械反对 |
| C-08 | Behavioral Conformance 有产品价值 | 商业假设 | 团队实际使用 | 无人需要 |
| C-09 | 企业需要跨 Harness 策略治理 | 商业假设 | 企业试点 | 普通配置已足够 |

## 9. 研究纪律

- 初始假设与结论分开保存；
- 负面结果不得隐藏；
- 使用最强合理基线；
- 重要任务预先冻结指标和隐藏集；
- 结论必须写适用范围和反证条件；
- 市场需求不能由技术可行性推导，必须独立验证；
- INA 必须允许实验杀死自己。
