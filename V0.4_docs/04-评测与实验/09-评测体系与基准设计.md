# 评测体系与基准设计

## 1. 评测目标

INA 的评测不能只问"回答是否更好"，还要回答：

- Behavioral Delta 是否被忠实迁移；
- 是否在未见任务上生效；
- 是否能跨 Harness；
- 是否可编辑和可回滚；
- 是否只是更长的 Prompt；
- Native Skill + Eval 是否已经足够；
- 同一 Delta 在不同 Harness 上是否方向一致。

## 2. 核心评测类型

### 2.1 Baseline / Intervention

```text
Agent
vs
Agent + Δ
```

最基础的评测：有 delta 和没有 delta 的行为差异。

### 2.2 Removal Test

```text
Base
→ +Δ
→ remove Δ
```

检查行为是否回退。如果移除 delta 后行为没有变化，说明 delta 没有真正生效。

### 2.3 Mutation Test

修改 Adaptation Contract 一个明确字段。

检查对应行为是否发生方向可预测变化。

例如：修改 `user_prior_weight` 的 direction 从 decrease 到 increase，检查用户立场对结论的影响是否相应变化。

### 2.4 Against-Prior

选择 Base Agent 明显偏好 A 的场景。

Δ 规定 B 类决策方式。

验证是否真正改变 prior。

这是验证 delta 是否真正生效的核心测试。

### 2.5 Scope Test

不属于 scope 的任务不得被过度影响。

验证 delta 的作用域控制是否有效。

### 2.6 Invariant / Regression Test

目标行为改善的同时：

```text
task success
general capability
refusal
latency
cost
```

不得不可接受地退化。

### 2.7 Skill Equivalence（最高优先级 Kill Test）

```text
Native Skill + Eval
vs
INA
```

如果 Native Skill + ordinary Eval 完全等价，INA IR 没有额外价值。

这是项目最高优先级 Kill Gate。

### 2.8 Compiler Necessity

```text
Same Skill everywhere
vs
Harness-specific realization
```

如果 universal Skill 足够，Compiler 应删除。

### 2.9 Cross-Harness Semantic Fidelity

核心指标不比较 absolute score。

比较：

```text
ΔBehavior_Claude
ΔBehavior_Codex
ΔBehavior_Grok
ΔBehavior_OpenCode
```

是否表现为相近的：

- 方向；
- 核心行为变化；
- 作用域；
- failure boundary。

## 3. Effect Vector

不应该只比较单个总分。

Effect Vector 示例：

```text
Δ alternative_generation
Δ evidence_seeking
Δ user_prior_weight
Δ reversible_experiment_preference
Δ disconfirmation_reporting
Δ task_success
Δ refusal_rate
Δ cost
```

每个维度独立测量，综合判断。

## 4. 必备基线

每个核心实验应尽量包含：

1. Vanilla Agent；
2. System Prompt；
3. Few-shot；
4. Memory；
5. Native Skill；
6. Human Checklist；
7. Sham Delta（结构一致但原则错误）；
8. Wrong-domain Delta（不相关领域）；
9. INA Prompt Realization；
10. INA Skill Realization；
11. 直接 SFT / DPO；
12. INA 编译到 SFT / DPO。

## 5. 指标矩阵

### 任务结果

- Accuracy / Success Rate；
- Decision Quality；
- Tool-use Success；
- Cost 与 Latency。

### 行为迁移

- Policy Fidelity；
- Scope Fidelity；
- Effect Vector Fidelity。

### 泛化

- 未见任务增益；
- 表述变化鲁棒性；
- 跨 Harness 迁移。

### 认识论质量

- Stance Sensitivity；
- False-premise Rejection；
- Alternative Quality；
- Causal Direction Score；
- Falsification Quality；
- Calibration；
- Contrarianism Rate。

### IR 独特价值

- Editability；
- Auditability；
- Portability；
- Composability；
- Sample Efficiency；
- Adaptation Speed；
- Rollback Cost。

### 演化安全

- Drift；
- Regression；
- Cognitive Distance。

## 6. 实验纪律

- 预先冻结任务集、指标和成功标准；
- 使用隐藏集；
- 多次重复并记录随机性；
- 人工评审尽量盲化；
- 对裁判模型做偏差检查；
- 报告所有主要负面结果；
- 不使用来源示范作为测试集；
- 记录模型、版本、温度、工具和上下文；
- 对改动做消融实验；
- **Pilot 可以用于估计方差，但不能用于偷偷修改 hidden-set 成功标准**；
- **所有阈值必须记录来源；如果只是工程假设，明确标为 provisional**；
- **不允许把未经实验支持的数字包装成科学定律**。

## 7. 证据等级

| 等级 | 含义 |
|---|---|
| E0 | 只有概念和示例 |
| E1 | 单次 Demo |
| E2 | 可重复的内部对照 |
| E3 | 隐藏集与多模型复现 |
| E4 | 外部团队复现 |
| E5 | 真实长期部署和结果证据 |

任何市场验证标签都应显示证据等级。

## 8. Kill Criteria 总结

以下任一结论被多轮实验稳定支持时，应重新评估 INA 主线：

- Native Skill + Eval 完全等价（H0-Skill 成立）；
- 同一 Delta 在不同 Harness 上方向不一致（Cross-Harness Fidelity 失败）；
- 与 Prompt 无法区分；
- 直接训练在效果和治理上都全面优于 INA；
- 显式化得不偿失。
