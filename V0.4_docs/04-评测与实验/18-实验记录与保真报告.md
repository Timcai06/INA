# 实验记录与保真报告

> [!NOTE]
> **HISTORICAL EVIDENCE — Cannot prove v0.4 H-Core**
>
> 本文档记录的是 v0.3 时期的合成数据实验（技术选型任务族），证据等级 E2。
> 这些实验证明了 Symbolic Extraction 在合成数据上的可行性，但不涉及：
> - Baseline Fingerprint
> - Cross-Harness Semantic Fidelity
> - Skill Equivalence Test
> - Adaptation Contract Schema (v0.4)
>
> 本卷可作为 E2 级 evidence 支撑 H1（可提取性）和 H3（可执行性）的早期证据，
> 但不能证明 v0.4 的 H-Core（跨 Harness 语义保真）。
>
> 本文档由 v0.3 文档 16 重编号而来，保留全部历史证据内容。

## 1. 目的与地位

本卷是 INA 已完成实验的**证据档案（执行记录）**，与 [14-首个验证实验方案](14-首个验证实验方案.md)（未执行的未来方案）区分：14 定义"将要做什么"，本卷记录"已经做了什么、结果如何"。

本卷收录 2026-08-05 完成的两轮合成数据实验（技术选型任务族）：

- 实验一：可行性试验（v1，理由文本信息完整）；
- 实验二：保真试验（v2，含噪、信息不足日志，one-shot 提取）。

证据等级：按 [09-评测体系与基准设计](09-评测体系与基准设计.md) 的等级定义，本卷证据等级为 **E2（可重复的内部对照）**，未达到 E3（隐藏集与多模型复现）与 E4（外部团队复现）。

## 2. 实验序列概览

| 维度 | 实验一（v1 可行性） | 实验二（v2 保真） |
|---|---|---|
| 样本 | train 20 / test 12（4 REJECT） | train 40 / test 20（3 REJECT） |
| 理由文本 | 明确泄漏权重（"社区活跃度优于 X"） | 90% 模糊、10% 可能指向错误因子 |
| 决策噪声 | 无（完全确定） | 8% 概率选次优（专家失误） |
| 干扰信息 | 无 | 每条 0-2 句无关内容 |
| 提取纪律 | 非强制 | one-shot，固化后不修改；不读 test |
| 真实权重排序 | community 第一（0.30） | maintenance 第一（0.30） |
| 结果 | 100%（12/12） | 90%（18/20） |
| 主要意义 | 证明提取→执行→对比成立 | 证明失败可归因于数据噪声 |

## 3. 实验一：可行性试验

### 3.1 目标

验证 INA 的核心主张是否成立：

> 能否从 Agent 的运行日志中提取出"可执行的决策模式"（INA），并让装载了 INA 的 Agent 在新场景中做出与专家一致的决策，从而显著优于"无 INA"的默认行为？

对应路线图 Phase 2 里程碑：A/B 测试证明 INA 有效性提升 >30%。

### 3.2 设计

| 环节 | 实现 | 说明 |
|---|---|---|
| 场景 | 技术选型（呼应 `pattern_tech_selection`） | 每场景 3 个候选库，5 个决策因子 |
| 数据 | 合成专家 Alice 的决策日志 | train 20 条（仅提取用）+ test 12 条（仅评估用），test 含 4 个 REJECT 场景 |
| 真实规则 | 五因子加权（0.30/0.25/0.20/0.15/0.10）+ 三条一票否决 red_flags | 与项目文档示例一致；**独立存储于生成脚本，不进日志** |
| 提取 | Reasonix 作为 LLM，只读 train 日志文本 | 产出 `ina/ina_tech_selection_alice_v1.json`，证据链见第 5 节 |
| 执行 | `ina_engine.py`：日志解析 → red_flags 否决 → 加权打分 → 选优/全否决 | 权重从 INA JSON 读取 |
| 评估 | `scripts/evaluate.py`：test 集 vs ground truth | 基线：stars 最高 / 五因子等权 / 随机 |
| 敏感性 | `scripts/sensitivity.py`：权重扰动 + 结构性压力测试 | 检验"精确提取"是否必要 |

**防泄漏设计**：提取只看 train；评估只看 test；ground truth 独立于日志存储。

### 3.3 主指标（test 集 12 场景：8 SELECT / 4 REJECT）

| 决策者 | 准确率 | 备注 |
|---|---|---|
| **INA** | **100%**（12/12） | select_acc 100%，reject_recall 100% |
| 无 INA：stars 最高 | 66.7% | 4 个 REJECT 场景全错（矮子里拔将军） |
| 无 INA：五因子等权 | 66.7% | 同上 |
| 无 INA：随机 | 8.3% | 最坏情形 |

**提升幅度**：INA vs stars/avg = **+50%**，vs random = +1100%。对赌 Phase 2 的 >30% 里程碑：**达成**（+50% ≥ 30%）。

### 3.4 敏感性分析（权重提取不精确时）

| 情形 | 准确率 |
|---|---|
| 权重 ±0.02/±0.05 随机扰动（200 次） | 100% |
| 权重 ±0.10 随机扰动（200 次） | min 91.7%，中位 100% |
| 删除 performance 因子 | 100% |
| 删除 completeness 因子 | 100% |
| 只保留 stars（community=1.0）+ red_flags | **100%** |
| 只保留 maintenance | 91.7% |

**关键洞察**：决策主要取决于"否决规则 + 因子排序"，对权重精读不敏感。
**最低可行 INA = red_flags 一票否决 + 粗略加权框架**——这降低了提取器的精度要求。

### 3.5 结论

**可行性判定：强可行（有保留）**。三个核心主张都得到支持：

1. **可提取**：决策模式可以从自然语言日志中归纳为结构化、可执行的形式；
2. **可执行**：INA JSON 可直接驱动 Agent 决策，无需额外微调；
3. **可提升**：相比无 INA 默认行为，有效性提升 +50%，超过里程碑阈值。

同时，"不选"的能力（red_flags → REJECT）是 INA 相对基线最大的价值来源——无 INA 者会在坏库里挑一个，INA 会拒绝整轮。

## 4. 实验二：保真试验

### 4.1 目标与 v1 的关键差异（全部针对失败空间）

消除 v1 实验的偏置（生成者=提取者、日志信息完整），检验**"从含噪、信息不足的日志中 one-shot 提取可执行决策模式"的保真度**。

| 维度 | v1（上轮） | v2（本轮） |
|---|---|---|
| 理由文本 | 明确写"社区活跃度优于X"（泄漏权重） | 90% 模糊（"综合评估后选定X"）、10% 可能指向错误因子 |
| REJECT 理由 | 明确列出三条 flag | 模糊（"质量不达预期"） |
| 决策 | 完全确定 | **8% 概率选次优（专家失误）** |
| 干扰信息 | 无 | 每条 0-2 句无关内容 |
| 提取纪律 | 非强制 | **one-shot，固化后不修改；不读 test** |
| 样本 | train 20 / test 12 | **train 40 / test 20** |
| 真实权重 | community 第一（0.30） | **maintenance 第一（0.30）**，community 0.25 |

真实权重（v2）：maintenance 0.30 / community_activity 0.25 / completeness 0.20 / team_familiarity 0.15 / performance 0.10。red_flags：单维护者 / 提交停滞 >180 天 / 无 TypeScript。

### 4.2 结果（test 20 场景：17 SELECT / 3 REJECT）

| 决策者 | 准确率 | 备注 |
|---|---|---|
| **INA（提取）** | **90.0%**（18/20） | 两个错误 V102/V106 恰为噪声决策场景 |
| 无 INA：stars | 75.0% | 3 个 REJECT 场景全错（选最高分坏库） |
| 无 INA：等权平均 | 70.0% | 含 1 个 REJECT 场景错 |

- 保真阈值（≥85%）：**PASS ✅**
- INA vs stars 提升：**+20.0 个百分点**
- 权重恢复：MAE = 0.000（五个因子全部与真实一致）

### 4.3 关键发现：失败可完全归因

两个错误场景 V102（pulsebox 胜 lumen-state）、V106（falconget 胜 reqnet）正是 ground truth 中 8% 噪声决策的位置——**专家选了次优，INA 选了特征最优**。

含义：90% 不是提取能力的上限，而是**数据噪声的上限**（1 - 噪声率）。提取出的 INA 与"提取的规则"行为完全一致，错误全部来自专家不可预测的随机性。这回答了 v1 实验留下的"失败不可归因"问题：**保真失败可以定位到数据噪声，而不是提取偏差**。

#### 独立评判（用户人工复核，2026-08-05）

对两个 INA 与专家不一致的场景（V102、V106）及三个 REJECT 场景（V105/V116/V119），用户作为独立评判者复核后表态：

| 场景 | 专家（ground truth） | INA | 独立评判 |
|---|---|---|---|
| V102 | pulsebox（噪声：选次优） | lumen-state | **认同 INA** |
| V106 | falconget（噪声：选次优） | reqnet | **认同 INA** |
| V105 / V116 / V119 | REJECT | REJECT | **认可"全部否决"** |

含义：

1. 两个"保真错误"场景在**决策质量**标准下，独立评判者认为 INA 的决策更合理——证实了实验设计中的噪声判断（专家失误），且提取出的 INA 去噪后甚至比专家本人的不一致行为更优；
2. 三个 REJECT 场景获得独立认可，确认 red_flags"不选"机制的价值成立；
3. **保真度（与专家一致）≠ 决策质量（合理性）**：以决策质量为标准，该 INA 在 test 集上达到 20/20；以保真度为标准为 18/20。

> 披露：评判者在展示时已看到"INA 选的是特征最优"的标注，存在一定诱导；独立评判仅覆盖 5 个重点场景，非全量 20 场景。

### 4.4 结论

**支持，但须限定条件**：

- ✅ 即使理由文本无信息、存在决策噪声和干扰，LLM 仍能从"决策结果 × 特征"的统计相关性中恢复专家决策规则（权重排序与 red_flags 均正确）；
- ✅ 提取的 INA 在未见过的 test 集上达到数据噪声上限（90%）；
- ⚠️ 保真度上限由噪声率决定：专家越不规律，可提取的认知上限越低（这是 INA 的理论边界：**认知提取保真度 ≤ 1 - 专家行为不可预测度**）。

## 5. 提取笔记与证据链

提取者：Reasonix（作为 LLM）。两轮提取均只读取 train 日志文本，不读取生成脚本的规则部分，不读取 test 集与 ground truth。

### 5.1 v1 提取（`ina/ina_tech_selection_alice_v1.json`，输入 `data/train_logs.json`，2026-04-03 ~ 04-22）

**权重排序证据**：理由文本在所有 SELECT 场景中高频出现同一句式「X 社区活跃度与维护节奏明显优于 Y，且团队已有上手经验」，由此推断权重排序：community_activity > maintenance > team_familiarity。

| 日志 | 证据点 |
|---|---|
| S001（4-03） | jetstream-http 胜 reqnet：社区活跃度不是只看 stars，提交新鲜度与发布节奏占权重 |
| S011（4-11） | testorn（stars 9679）胜 spectra-test（stars 14025）：stars 落后 45% 仍胜出，familiarity + completeness 有真实权重 |
| S019（4-19） | pulsebox 险胜 atomize：接近场景下由 familiarity 与 performance 拉开差距 |
| S020（4-21） | quillnet（familiarity 4）胜 reqnet（completeness 91%）：stars 权重高于 completeness 的旁证 |

权重定值：community 0.30 / maintenance 0.25 / familiarity 0.20 / completeness 0.15 / performance 0.10（依据：理由文本的提及顺序与频率；数值本身是归纳估计，非精确测量）。

**red_flags 证据**：4 个 REJECT 场景（S005 4-07 / S006 4-08 / S007 4-09 / S013 4-16）理由原文相同：「所有候选均存在不可接受的硬伤（单维护者 / 长期未更新 / 缺少 TypeScript 支持）」。逐条核实（S005）：verifox 命中 stale_commit + no_typescript；spectra-test 命中 no_typescript；vivid-test 命中 single_maintainer + stale_commit。

阈值定值：last commit > 180 天视为"长期未更新"（观察到的 REJECT 场景提交停滞 170~345 天，SELECT 场景普遍 < 60 天；取 180 天即"半年"作为分界）。

**fallback**：REJECT 场景的决策动作是「全部否决，不引入」「暂缓引入新依赖」——与 INA 文档示例中"选择社区最活跃的并计划贡献"不同，以实际观察行为为准。

**特征归一化边界**：train 数据取值范围 stars 483~14895、last_commit 11~345 天、release 1~17 月、issues 26~480、familiarity 0~5、completeness 0.34~0.95、bundle 35~195kb、render 8~60ms。归一化阈值（15000/180/12/300/5/150/60）按这些范围选取，使满量程映射到 0~1。

### 5.2 v2 提取（`ina/ina_tech_selection_alice_v2.json`，one-shot，固化后不再修改，输入 `data_v2/train_logs.json`）

**数据噪声环境（提取者感知到的）**：

- 理由文本 90% 模糊（"综合评估各候选后选定 X"等），10% 具体但可能指向错误因子 → **权重无法从理由中读取，只能从"决策结果 × 特征"统计归纳**；
- 干扰句 0-2 条/日志（会议纪要等），与决策无关；
- 观察到个别决策与特征显著相悖（如 V032 spectra-test 胜 verifox）→ 判断存在不可复现的随机性（专家失误），此类场景注定无法由任何确定性 INA 复现。

**权重排序证据（关键反例：stars 落后仍胜出）**：

| 日志 | 场景 | 胜者（stars 较低） | 败者（stars 较高） | 胜出原因 |
|---|---|---|---|---|
| 5-20 | UI 组件库 | cobalt-ui 8949 | aurora-kit 13155（-4206） | rel 1月/issues 65/comp 87/fam 4/perf 40kb·9ms |
| 5-31 | 状态管理 | pulsebox 9072 | stateforge 14772（-5700） | commit 10天/rel 1月/bundle 34kb |
| 5-38 | 构建工具 | bundlefast 8246 | swiftbuild 12266（-4020） | issues 23 vs 107/comp 91 vs 84/fam 4 vs 3 |

正向证据：5-14、5-23、5-27、5-30、5-39 等 stars 最高者胜出（community 有分量但不是第一）。5-13（comp 90 胜出）、5-15（quillnet issues 27 + comp 88 胜 reqnet）→ completeness 分量第三。

归纳权重：maintenance 0.30 > community_activity 0.25 > completeness 0.20 > team_familiarity 0.15 > performance 0.10。

**red_flags 证据**：9 个 REJECT 场景（5-01/5-06/5-07/5-11/5-18/5-25/5-26/5-35/5-36）的候选无一例外命中以下至少一条：

- 仅由一位维护者维护（5-06 cobalt/aurora、5-07 全、5-18 atomize/vortex、5-25 stateforge/lumen、…）；
- 最近一次提交 > 180 天（5-01 252-340 天、5-11 270-386 天、5-36 224-337 天、…）；
- 不提供 TypeScript 类型定义（5-06、5-07、5-11、5-18、5-25、5-26、5-35、5-36）。

阈值：180 天（被拒候选停滞 224-386 天，胜者普遍 <120 天；无中间地带需要细分）。

**v2 局限声明**：提取者同时是数据生成者，权重归纳存在先验污染风险；缓解：归纳完全基于日志中的可观察反例（上述表格），且本版本权重排序与 v1 不同（v1 为 community 第一），非记忆复读。噪声决策（约 8%）不可复现，计入预期失败空间。

## 6. 跨实验结论

1. **认知提取保真度 ≤ 1 - 专家行为不可预测度**：保真上限由数据噪声率决定，与提取器精度无关（实验二 90% ≈ 1 - 8% 噪声率）；
2. **最低可行 INA = red_flags 一票否决 + 粗略加权框架**：决策主要由否决规则与因子排序决定，权重精读不必要（实验一敏感性分析）；
3. **对 [03-研究章程与可证伪假设](../01-宪法与研究基线/03-研究章程与可证伪假设.md) 的证据状态**：支持 H1（可提取性，限定：合成日志、技术选型窄任务族、Symbolic 提取）与 H3（可执行性，限定：INA JSON 直接驱动决策）；不触及 H2/H4/H5；
4. **"不选"能力是最大价值来源**：red_flags → REJECT 相对基线的增益（+20~50 个百分点中的主要部分）来自拒绝整轮坏库；
5. 本卷证据等级 E2：可重复的内部对照，样本量小，不构成 E3/E4 级证据。

## 7. 局限与诚实声明（必须阅读）

1. **提取偏置**：提取者（Reasonix）同时是数据生成者，v1 提取权重与真实规则完全一致（diff=0.00）、v2 权重 MAE=0.000，均不能视为纯归纳能力的证明；真实场景提取不会如此精确。缓解：v2 权重排序与 v1 不同（maintenance 第一 vs community 第一）且基于日志内可观察反例；v1 敏感性分析表明权重 ±0.05 偏差下依然 100%，结论对偏置有一定耐受；
2. **样本量小**：test 仅 12/20 场景，100%（12/12）与 90%（18/20）的置信区间宽（90% 的 95% 置信区间约 68%~99%，与阈值 85% 的差距在统计上不显著）；建议扩充到 ≥100 场景复测；
3. **合成数据规整**：日志由脚本生成（格式固定、特征完整），regex 解析即可；真实 Agent 日志噪声大、特征缺失/表述多样，解析层（INA-seq 的结构化环节）需要 LLM 或更鲁棒的抽取，未在本实验验证；
4. **同分布泄漏**：test 与 train 同分布（同一生成器）。真实场景的分布漂移（如新领域、新指标）未被检验；
5. **无 evolve 验证**：两轮实验只验了提取→执行→对比，`evolve()`（反馈进化）未纳入——那是 INA 区别于静态文档的另一个关键主张，需单独试验；
6. **独立评判范围有限**：评判者事先看到"INA 特征最优"的标注，存在诱导；仅覆盖 5 个重点场景。全量盲评（评判者不知各方身份）是下一步可选验证。

## 8. 建议的后续实验

- [ ] 扩充 test 集至 ≥100 场景、引入分布漂移子集，复测 100%/90% 是否保持；
- [ ] 用真实（非合成）Agent 对话日志做提取，验证解析层鲁棒性；
- [ ] 单独设计 evolve() 试验：注入失败反馈，验证 INA 自动优化；
- [ ] 嫁接引擎（Grafting）最小试验：两个 INA 融合后在新域的表现。

与 [14-首个验证实验方案](14-首个验证实验方案.md) 的衔接：14 定义的"用户立场干扰下的技术选型"实验及其交付物（任务数据集、INA Artifact、Compiler、盲评、消融报告）应在本卷基线之上执行，并复用本卷的防泄漏纪律与归因方法。

## 9. 复现
