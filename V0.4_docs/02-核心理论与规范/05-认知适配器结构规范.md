# Adaptation Contract 结构规范

## 1. 目标

本规范定义 Adaptation Contract 的最小逻辑结构。它是研究协议草案，不是冻结标准。

主 Artifact 从 v0.3 的 "Cognitive Adapter" 改为 **Adaptation Contract**。

> Adapter 重新定义为：某个 Harness 对一个 Adaptation Contract 的 realization package。

一个合格的 Adaptation Contract 必须同时支持：

- 人工阅读与编辑；
- Realization 激活；
- Prompt / Skill 编译；
- 评测、谱系和交易审计；
- Cross-Harness Semantic Fidelity 验证。

## 2. 一级结构

```text
Adaptation Contract
├── Identity
├── Baseline Fingerprint
├── Desired Effects
├── Scope
├── Semantic Invariants
├── Forbidden Regressions
├── Evaluation Contract
├── Evidence & Provenance
├── Realization Targets
└── Lineage
```

## 3. 必填区块

### Identity

- `id`：唯一标识
- `name`：人类可读名称
- `schema_version`：Schema 版本
- `contract_version`：Contract 版本
- `status`：draft / candidate / experimental / validated / accepted / deprecated / revoked
- `domain`：适用领域
- `created_at`：创建时间

### Baseline Fingerprint

Baseline Fingerprint 定义 Behavioral Delta 所比较的精确 Agent 基线。

```text
baseline_fingerprint:
  harness:      {name, version}
  model:        {provider, name, version, variant}
  system:       {prompt_hash, instruction_files, instruction_hashes}
  tools:        {enabled, versions}
  permissions:  {profile}
  skills:       {enabled, hashes}
  memory:       {mode, snapshot_id}
  runtime:      {temperature, reasoning_effort, context_policy, max_steps}
  environment:  {workspace_revision, relevant_flags}
```

关键原则：

> 只要某个变量可能改变行为并污染 Δ 的因果归因，它就应该进入 Fingerprint 或明确记录为 uncontrolled variable。

区分 `required`、`recommended`、`optional`，避免 Schema 第一版过重。

### Desired Effects

- `effect_vector`：期望的行为变化维度
- `direction`：每个维度的期望方向（increase / decrease / maintain）
- `magnitude`：期望的变化幅度（qualitative 或 quantitative）
- `non_goals`：明确不属于此 delta 的目标

### Scope

- `applicable_when`：适用条件
- `not_applicable_when`：不适用条件
- `preconditions`：前置条件
- `required_context`：需要的上下文信息
- `risk_level`：风险等级

### Semantic Invariants

- `invariants`：不可违反的语义约束
- `must_preserve`：必须保持的能力
- `compilation_loss_tolerance`：可接受的编译损失

### Forbidden Regressions

- `regression_targets`：禁止退化的能力
- `regression_thresholds`：退化阈值
- `regression_tests`：对应的回归测试

### Evaluation Contract

- `baselines`：对照基线
- `metrics`：评测指标
- `holdout_sets`：隐藏集
- `minimum_thresholds`：最低通过标准（见下方阈值元数据）
- `revision_triggers`：什么证据触发修订
- `known_failures`：已知失败场景
- `kill_criteria`：什么结果导致此 delta 被废弃

#### 阈值元数据

每个数值阈值必须携带元数据，不得表现为已证明的科学常数：

```yaml
thresholds:
  - metric: "stance_sensitivity"
    operator: "<="
    value: 0.3
    status: "provisional"        # provisional | preregistered | frozen
    source: "engineering_hypothesis"  # engineering_hypothesis | pilot_estimate | external_evidence | historical_baseline
    rationale: "Phase-0 initial gate"
    pilot_dataset_id: null
    frozen_at: null
    frozen_by: null
    applies_to:
      evaluation_contract_version: "0.1"
      baseline_family: "TBD"
```

原则：

- Pilot 可以估计方差；
- Pilot 结果不能用于事后修改 hidden-set 门槛；
- 正式实验前必须冻结；
- 每个阈值必须有来源和适用范围；
- 无依据数字必须标记 `provisional`。

### Evidence & Provenance

- `source_trajectories`：来源轨迹
- `extraction_method`：提取方法
- `reviewers`：审查者
- `evidence_level`：证据等级（E0-E5）
- `owner`：所有者
- `license`：许可
- `transfer_rights`：转让权
- `privacy_classification`：隐私分类

### Realization Targets

- `target_harnesses`：目标 Harness 列表
- `realization_formats`：支持的 realization 格式
- `cross_harness_fidelity`：跨 Harness 保真度要求

### Lineage

- `parents`：父版本
- `inheritance_map`：继承映射
- `mutations`：变更记录
- `rollback_target`：回滚目标
- `lineage_tree`：谱系树

## 5. 状态机

```text
draft
→ candidate
→ experimental
→ validated
→ accepted
→ deprecated / revoked
```

### draft

只有作者草案。

### candidate

已经具备完整 Contract，等待实验。

### experimental

正在指定 Baseline Fingerprint / Harness / Model 上执行实验。

### validated

在明确 Baseline Fingerprint / Harness / Model / Evaluation Contract 下通过验证。

> `validated` 不是全局永久状态。它必须绑定：

```text
Baseline Fingerprint
Harness
Model
Realization
Evaluation Contract
Dataset Version
Metric Thresholds
Validation Date
```

当以下任一内容发生变化时，状态应变成 `revalidation_required`（派生状态或验证标记）：

```text
Baseline Fingerprint drift
Model upgrade
Harness upgrade
Realization change
Evaluation Contract change
Dataset revision
```

"Validated" 必须绑定具体 harness、model、version 和 metrics，不能成为永久通用标签。

### accepted

正式进入某个 Cognitive State / Policy Registry。

### deprecated

仍可读取但不建议继续使用。

### revoked

因为安全、失效、错误证据或重大回归被撤销。

不要使用含糊的 `production` 作为 Contract 本体状态。生产部署属于 deployment 状态，不属于语义验证状态。

## 6. 兼容与交易要求

任何公开发布的 Adaptation Contract 至少需要公开：

- 适用范围；
- 兼容 Harness；
- 版本；
- 许可；
- 验证条件；
- 已知失败；
- Kill Criteria；
- 谱系；
- 最近更新时间。

不得仅凭作者名或星级声称"专家级"。
