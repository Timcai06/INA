# Behavioral Adaptation IR

## 1. 为什么需要 IR

微调把经验压缩进权重，Prompt 把要求临时放入上下文，Memory 保存历史事实。三者都能改变 Agent 行为，但缺少一个统一层来回答：

- 这次行为变化具体代表什么 delta；
- 它适用于哪些场景；
- 它如何被修改、验证和回滚；
- 它能否换 Harness 继续使用；
- 它与另一个 delta 为什么冲突；
- 它是否有权被共享和交易。

INA 的核心假设是：在经验和行为之间，可以存在一层独立的行为适应表示。

```text
Experience / Feedback / Outcomes
        ↓
Adaptation Learner
        ↓
Candidate Behavioral Delta
        ↓
INA Validation
        ↓
Accepted Delta
        ↓
Realization (Skill / Hook / Prompt / ...)
        ↓
Agent Behavior
        ↓
Effect Extraction
        ↓
Conformance Check
```

## 2. 核心三角

```text
                 Representation
                /              \
               /                \
      Extraction -------------- Execution
```

### Extraction

从可观测行为中识别稳定的行为变化。

### Representation

以模型无关的方式表达 scope、desired effects、invariants、evidence、evaluation contract。

### Execution

把 delta 转换为能改变具体 Agent 行为的形式（realization）。

任何一角失败，INA 的完整主张都无法成立。

## 3. Behavioral Delta

INA 不表示完整智能，而表示相对基准的行为增量：

```text
Effect_h(Δ | F) = Behavior(A_h(F) + Realize_h(Δ)) - Behavior(A_h(F))
```

其中 `F = Baseline Fingerprint`。

多个 delta 可以写为：

```text
Cognitive State(t) = Accepted Δ1 + Accepted Δ2 + ... + Accepted Δn
```

这里的加号不是简单拼接，而代表经过路由、优先级和冲突解析后的组合。

> **没有 Baseline Fingerprint，就没有严格意义上的 Behavioral Delta 因果归因。**

## 3.1 Agent Baseline Fingerprint

Agent Baseline Fingerprint 表示 Behavioral Delta 所比较的精确 Agent 基线：

```yaml
baseline_fingerprint:
  harness:
    name: "harness name"
    version: "harness version"
  model:
    provider: "provider"
    name: "model name"
    version: "model version"
    variant: "model variant"
  system:
    prompt_hash: "hash of system prompt"
    instruction_files: ["list of instruction files"]
    instruction_hashes: ["hashes of instruction files"]
  tools:
    enabled: ["list of enabled tools"]
    versions: ["tool versions"]
  permissions:
    profile: "permission profile"
  skills:
    enabled: ["list of enabled skills"]
    hashes: ["skill hashes"]
  memory:
    mode: "memory mode"
    snapshot_id: "memory snapshot id"
  runtime:
    temperature: 0.0
    reasoning_effort: "reasoning effort"
    context_policy: "context policy"
    max_steps: 100
  environment:
    workspace_revision: "git revision"
    relevant_flags: ["list of relevant flags"]
```

关键原则：

> **只要某个变量可能改变行为并污染 Δ 的因果归因，它就应该进入 Fingerprint 或明确记录为 uncontrolled variable。**

不要机械认为所有字段第一版都必须获得。区分 `required`、`recommended`、`optional`。

## 4. IR 的核心字段

一个完整的 Behavioral Adaptation IR 应包含：

```text
Behavioral Delta
├── Identity (id, version, status)
├── Baseline Fingerprint (what exactly is the baseline)
├── Desired Effects (what behavioral changes are expected)
├── Scope (when does this delta apply)
├── Semantic Invariants (what must not change)
├── Forbidden Regressions (what capabilities must not degrade)
├── Evidence (what supports this delta)
├── Provenance (who created it, from what)
├── Evaluation Contract (how to verify this delta)
├── Realization Targets (which harnesses)
└── Lineage (version history, parent deltas)
```

## 5. 语义不变量

无论 realization 到哪种 Harness，以下语义应尽量保持：

- 适用范围；
- 核心偏好；
- 认识论约束；
- 禁止和升级条件；
- 失败边界；
- 置信度策略；
- 可被什么证据修正。

如果 realization 丢失这些信息，需要记录 Realization Loss。

## 6. Realization Fidelity

用于衡量 realization 后行为是否仍忠实于 Symbolic Delta。

建议分为：

- **Policy Fidelity**：核心策略是否保持；
- **Scope Fidelity**：是否只在适用情境激活；
- **Epistemic Fidelity**：证据、反证和不确定性纪律是否保持；
- **Failure Fidelity**：是否仍能识别原定义的失败边界；
- **Edit Fidelity**：修改源 Delta 后，realization 是否产生预期变化。

## 7. Cross-Harness Semantic Fidelity

v0.4 最核心的验证问题之一：

> 同一 Δ 在多个 Harness 中通过不同 realization 后，是否产生方向一致、语义一致的 baseline-relative behavioral effect。

不同 Harness 拥有不同 Baseline，因此跨 Harness 比较不是绝对行为相同，而是方向一致：

```text
Direction(Effect_Claude(Δ | F_Claude)) ≈ Direction(Effect_Codex(Δ | F_Codex)) ≈ Direction(Effect_Grok(Δ | F_Grok)) ≈ Direction(Effect_OpenCode(Δ | F_OpenCode))
```

其中 `F_h` 是该 Harness 下具体 Agent 的 Baseline Fingerprint。

> 同一个 Behavioral Delta 可以在不同 Harness 上有不同实现，但应该产生方向一致、语义一致的行为变化。

核心指标不比较 absolute score。比较方向、核心行为变化、作用域、failure boundary 是否一致。

## 8. 为什么不是完整符号主义

INA 不试图把所有推理步骤写成规则。

保留给基础模型的能力包括：

- 模糊语义理解；
- 类比和创造；
- 长尾上下文处理；
- 自然语言生成；
- 不完全信息下的柔性推理。

INA 只显式化那些值得控制、迁移、评测、组合和交易的行为结构。

## 9. IR 成立的最低证明

1. 同一 Symbolic Delta 可 realization 到至少两个 Harness；
2. 两个 Harness 的行为都保留核心语义（方向一致）；
3. 修改 Symbolic Delta 能导致可预测的行为变化；
4. 这种显式层带来至少一项直接方案难以获得的价值；
5. Skill Equivalence Test 没有杀死 INA。
