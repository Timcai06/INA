# 研发路线图与阶段门禁

## 1. 原则

路线图不以固定月份作为主要承诺，而以证据门槛决定是否进入下一阶段。

产品 UI 和完整 PRD 当前不是重点。第一批工作是文档、协议、实验和核心模块。

所有阶段门槛数字均为 **Phase-0 preregistered provisional thresholds**，在 Pilot 阶段估计方差后正式冻结。正式实验前不得偷偷修改 hidden-set 成功标准。

## 2. Phase 0A：Delta Causality

### 目标

证明 Behavioral Delta 可以被定义、测量和验证。

### 交付

- Adaptation Contract Schema；
- 最小评测框架；
- Effect Vector 计算；
- 至少一个 delta 的 add / remove / mutate / against-prior / scope / regression 测试。

### 门禁

- Add Test：delta 产生可测量的行为变化；
- Removal Test：移除 delta 后行为回退；
- Mutation Test：修改 contract 字段导致可预测行为变化；
- Against-Prior：delta 真正改变 Agent 的 prior；
- Scope Test：delta 不过度影响 out-of-scope 任务；
- Regression Test：task success / general capability 不可接受退化。

## 3. Phase 0B：Skill Equivalence（最高优先级 Kill Gate）

### 目标

强制判断：INA vs Native Skill + ordinary Eval。

### 交付

- Native Skill 实现（与 Adaptation Contract 等量自然语言原则）；
- Skill Equivalence Test；
- 消融报告。

### 门禁

- 如果 Native Skill + Eval 完全等价 → **项目停止或 Pivot**；
- 如果 INA 有至少一项可量化优势 → 继续。

这是项目最高优先级 Kill Gate。**H0-Skill 未成立后才允许进入 Phase 1。**

## 4. Phase 1：Cross-Harness Fidelity

### 目标

证明 same Δ → different realization → same-direction effect。

### 交付

- 2 个 Harness Adapter；
- Paired Replay 基础设施；
- Cross-Harness Semantic Fidelity 指标。

### 门禁

同一 delta 在两个 Harness 上：

- 方向一致；
- 核心行为变化一致；
- 作用域一致。

### Harness 选择

首批实验 Harness 必须满足 Harness Selection Criteria（见第 13 节）。最终选择通过 ADR 决定。

## 5. Phase 2：四 Harness Conformance

### 目标

扩展到 4 个 Harness，验证大规模 Cross-Harness Fidelity。

### 交付

- 4 个 Harness Adapter；
- 完整 Conformance 测试；
- CI Report。

### 门禁

- 4 个 Harness 上方向一致；
- Conformance 结果可复现。

## 6. Phase 3：Compiler（条件触发）

### 目标

只有在证明 Harness-specific realization 确实必要后才做。

### 交付

- Prompt Compiler；
- Skill Compiler；
- Compilation Loss 报告。

### 门禁

- Universal Skill 不够，Harness-specific realization 有显著优势。

## 7. Phase 4：Registry / Version / Lineage

### 目标

建立完整的版本管理和谱系追踪。

### 交付

- Registry 服务；
- 版本管理；
- 谱系追踪；
- Rollback 机制。

## 8. Phase 5：Trajectory → Candidate Δ

### 目标

开始真正的 Adaptation Learner。

### 交付

- INA-seq 实现；
- Candidate Δ 提取；
- 人工审查流程。

### 门禁

- 提取结果在未见任务上复现来源 delta；
- 明显优于表面总结。

## 9. Phase 6：Validated Evolution

### 目标

在正确归因和回归保护下，Delta 能从新经验中改善。

### 交付

- Credit Assignment；
- Replay + Regression；
- Cognitive Distance 检查；
- Rollback 机制。

## 10. Phase 7：Enterprise Control Plane / Marketplace / Personal Layer

### 目标

在核心认知资产成立后验证商业假设。

### 交付

- Enterprise 私有 Registry；
- Marketplace（如验证成立）；
- Personal Delta。

### 门禁

存在真实复用、付费或企业部署证据。

## 11. 停止条件

遇到以下情况应暂停扩张或 Pivot：

- Native Skill + Eval 完全等价（H0-Skill 成立）；
- 同一 Delta 在不同 Harness 上方向不一致；
- 与 Prompt 无法区分；
- Direct Fine-tuning 全面更优且 INA 无治理增益；
- 用户不愿为认知资产复用付费。

## 13. Harness Selection Contract

首批实验 Harness 必须满足：

```text
1. 可自动化执行
2. 可尽量固定模型和 Harness 版本
3. instruction / skill / hook 等 realization surface 可控
4. 能获得足够的执行结果与 trace
5. 两个 Harness 的 realization surface 存在一定结构差异
6. 测试成本可接受
7. 可以重复运行
```

最终选择通过 ADR 决定，不得提前写死。

- **高价值候选**：Claude Code + Codex（realization surface 差异大）
- **优先候选**：OpenCode + Grok Build（自动化执行成本低）
