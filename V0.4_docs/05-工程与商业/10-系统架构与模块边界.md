# 系统架构与模块边界

## 1. 架构目标

v0.4 架构以 Behavioral Adaptation Control Plane 为中心。

核心原则：

> **Harness Runtime 属于执行环境；INA 通过 Adapter/Realization 与之集成。**

Runtime 不是 INA 的主战场。Harness 已经有 Runtime。

## 2. 架构边界

    candidate Δ  (not INA's responsibility)

## 3. Phase 0 最小系统

```text
ina-schema
  Schema、校验、版本兼容

ina-contracts
  Adaptation Contract 管理、版本、状态

ina-adapters
  Harness Adapter、realization mapping

ina-runner
  Paired Replay 执行、Effect Extraction

ina-eval
  Benchmark、基线、Effect Vector 计算

ina-conformance
  Cross-Harness Fidelity、Against-Prior、Regression

ina-report
  CI Report、结构化输出
```

## 4. 推荐流程

```text
Capture Baseline Fingerprint
        ↓
Validate Fingerprint Integrity
        ↓
Load Candidate Δ from Adaptation Learner
        ↓
Manifest / Adaptation Contract
        ↓
Realization
        ↓
Baseline Run + Adapted Run
        ↓
Fingerprint Equality Check
        ↓
Effect Extraction
        ↓
Conformance
        ↓
Pass / Fail / Invalid
```

## 5. 核心实体

- `AdaptationContract`：行为适应契约
- `BaselineFingerprint`：Agent 基线指纹，所有 paired comparison 的前提
- `HarnessAdapter`：Harness 适配器
- `Realization`：具体实现
- `EvaluationContract`：评测契约
- `PairedReplay`：配对重放
- `EffectVector`：效应向量
- `ConformanceResult`：合规结果
- `Report`：结构化报告

## 6. 模块边界原则

- Schema 不依赖具体模型 SDK；
- Control Plane 不拥有 Harness 的执行状态；
- Realization 必须可追溯到源 Contract；
- Eval 不依赖单一裁判模型；
- Conformance 不能绕过 Evaluation Contract；
- Report 不能污染执行语义；
- `ina-runner` 不得在 baseline/adapted 两侧偷偷改变配置；
- `ina-report` 必须展示 Baseline Fingerprint；
- `ina-conformance` 必须拒绝 Fingerprint 不一致的结果（标记为 INVALID）；
- `ina-adapters` 的 realization 必须能被 hash 和追踪；
- Baseline Fingerprint 应成为 Conformance Result 的组成部分。

## 7. 隐私和企业部署预留

从第一版起区分：

- Public Delta；
- Private User Delta；
- Team Delta；
- Enterprise Restricted Delta。

轨迹默认不因购买或交易而共享。交易的是 Adaptation Contract 及其许可，不是原始私人对话。
